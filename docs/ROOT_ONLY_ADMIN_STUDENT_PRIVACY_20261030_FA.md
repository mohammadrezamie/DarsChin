# قرارداد روت یکتا، مدیریت غیرعمومی و حساب دوپنلی

> تاریخ: ۲۰۲۶/۱۰/۳۰ — وضعیت: تغییر در شاخهٔ PR؛ تایید QA/مرج/دیپلوی باز

## رفتار مورد انتظار

۱. صفحهٔ ورود، لندینگ، راهنمای عمومی و دموی آزاد تنها دربارهٔ تجربهٔ دانشجویی حرف می‌زنند. لینک /demo/admin صرفاً برای دارندهٔ نشست و مجوز مدیریتی معتبر قابل استفاده است؛ پنهان‌سازی لینک هرگز جایگزین authz سمت سرور نیست.
۲. فقط روت سراسری مجاز به فهرست‌کردن مدیران و ایجاد، ویرایش، تغییر نقش، تخصیص دسترسی و فعال/غیرفعال‌کردن آن‌هاست. نقش admin و permissionهای تفویض‌شده نمی‌توانند به‌تنهایی مدیر جدید بسازند یا نقش دیگری را تغییر دهند.
۳. هر مدیر در همان حساب به فضای دانشجویی خود و (در صورت مجوز) بخش مدیریتی دسترسی دارد. نقش student هنگام ایجاد مدیر یا ویرایش نقش‌ باقی می‌ماند. حذف نقش admin نباید سوابق دانشجویی را حذف کند.
۴. گوشی تجربهٔ اپلیکیشنی با bottom dock، safe area، پیمایش کوتاه و جریان مرحله‌ای دارد؛ دسکتاپ نمای مستقلی دارد. این اصلاح امنیتی به معنای اتمام پروژهٔ بازطراحی موبایل/مدیریت نیست.

## یافتهٔ ممیزی

- در main پیش از PR، صفحهٔ Login لینک عمومی ورود به دمو مدیر داشت.
- در مسیر admin-management مجوزهای admin.create/admin.manage/admin.remove به نقش تفویضی اختیار مدیریت دیگران می‌دادند؛ بدون دانشجوکردن خودکار ادمین جدید.
- منطق ریدایرکت login با گیت adminWorkspaceAccess هم‌خوانی نداشت.

## تحویل این برش

- requireSuperAdmin برای GET/POST/PUT/DELETE مدیریت مدیران؛ مسیر PUT محدودهٔ نیازسنجی از قبل روت‌محور است.
- admin جدید دارای نقش‌های student و admin؛ با تنزل فقط student باقی می‌ماند.
- حذف CTA دموی مدیریت از صفحهٔ ورود عمومی؛ استفادهٔ یکسان از گیت role+permission برای مسیریابی پس از ورود.
- تست‌های منبع برای ممنوع‌بودن تبلیغ مدیریت و تست API برای ممانعت از عملیات تفویضی و بقای نقش دانشجو.

## دروازهٔ پذیرش (هنوز انجام‌نشده)

- اجرای bun run qa:full روی clone دقیق HEAD با frozen deps، Vitest، TypeScript، build و disposable API smoke؛ نتایج و SHA باید ثبت شود.
- بازآزمایی واقعی ساخت مدیر توسط روت، ورود مدیر به دو میز کار، تنزل و حفظ پرونده؛ درخواست‌های مدیر تفویضی با permissionهای قدیمی باید 403 بگیرند.
- آزمون iOS Safari/Android Chrome و حالت نصب PWA، عرض‌های ۳۲۰ تا ۱۴۴۰ و RTL/روز/شب.
- بدون تست کامل، PR نباید مرج شود. بدون گیت مستقل و اجازهٔ مالک، deploy روی VPS ممنوع است. پروژهٔ TNA خواندنی و بدون تغییر.

## باقیمانده‌های قطعی

- بازنویسی جامع پنل مدیریت و انتخاب‌گرهای سلسله‌مراتبی نامی و گراف بصری وابستگی‌ها.
- سنجش واقعی استاد و ترکیب گروه‌ها، تعارض امتحان و روزهای حضور، تست‌های UX موبایل.
- بررسی چارت معارف پس از توضیح و تایید صاحب محصول؛ بدون فرض جدید دربارهٔ قوانین دانشگاه آزاد.
