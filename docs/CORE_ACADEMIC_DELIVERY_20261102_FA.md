# وضعیت واقعی قابلیت‌های اصلی درس‌چین — ۲ نوامبر ۲۰۲۶

## درخواست مالک و اولویت جدید

درخواست صریح: به‌جای اصلاحات کوچک تکراری، **مدیریت چارت دانشگاه/مقطع/رشته/ورودی، جریان درس→استاد، برنامه‌ساز با کمترین روز/زمان و استاد بهتر، برنامه‌ریزی تا فارغ‌التحصیلی** در اولویت باشند.

### آنچه قبل از این تغییر واقعاً در کد بوده
- فرم ساخت چارت برای دانشگاه، واحد، مقطع، رشته و ورودی؛ جداول اتصال درس و پیش/هم‌نیاز در پنل مدیریت و API دارای مجوز. **فعال‌سازی مشخص در همان صفحه ناقص بود**؛ یک پیش‌نویس ساخته می‌شد اما مسیر انتشار کاربرپسند نبود.
- انتخاب ابتدا درس، سپس استاد و گروه‌های جایگزین و صف مشترک: پیاده شده، نیازمند آزمون مرورگری و شفاف‌سازی باقی‌مانده.
- موتور پیشنهاد شفاف بر اساس **تمام زنجیرهٔ دروس وابسته تا پایان چارت** در `src/domain/recommendation-engine.ts` وجود دارد، اما این **به معنای ساخت نقشهٔ جامع ترم‌به‌ترم تا فارغ‌التحصیلی نیست**.
- رتبه‌بندی معلمان `src/domain/teacher-ratings.ts` فقط دادهٔ مصنوعی مرورگر را دارد؛ اتصال امتیاز واقعی استادان و سازوکار اطمینان/حریم خصوصی **تکمیل نشده**.
- برنامه‌ساز خودکار برای سقف ۲/۳/۴/۵ روز **وجود نداشت**.

### تغییر جدید این PR
۱. ایجاد موتور جستجوی محدود و قطعی `src/domain/smart-schedule.ts` بر مبنای گروه‌های واجد صلاحیت، زمان کلاس معتبر، تداخل کلاس و شروع امتحان، سقف روزهای حضور و ترجیح استاد خود دانشجو؛ برای سرعت موبایل تعداد حالت‌ها محدود است و هیچ نتیجه‌ای **اثبات عدم امکان قطعی** نیست.
۲. رابط ساخت ۲ تا ۵ روزه در **مرحله دوم همان گردش درس→استاد و صف مشترک**؛ پیش‌نمایش قابل فهم و **دکمه تأیید مجزا**. ذخیرهٔ یکجای پیشنهاد در API واقعی برنامه با کنترل کامل سرور انجام می‌شود؛ هیچ ثبت خودکار آموزشیار رخ نمی‌دهد. انتخاب‌های سابق خارج از سبد بی‌اجازه حذف نمی‌شوند؛ اگر مانع ترکیب شوند، سرور کل پیشنهاد را رد می‌کند.
۳. در مدیریت چارت، نشان دادن تعداد درس‌ها و روابط و دکمهٔ انتشار پیش‌نویس پس از تأیید مدیر. سرور انتشار بدون درس فعال و وجود چارت فعال دیگر در همان دانشگاه/واحد/مقطع/رشته/ورودی را رد می‌کند و در خطای ذخیره، تغییر وضعیت را برمی‌گرداند.
۴. تست الگوریتم، یکپارچگی API انتشار، و تست حفظ اطلاعات؛ لندینگ، دمو و سرور مستقر فعلی تغییر نمی‌کنند.

### کارهای باقیمانده (P0/P1، **انجام‌شده تلقی نشوند**)
- **P0:** تکمیل و آزمون سرتاسری پنل مدیریت چارت: فیلترهای آبشاری دقیق واحد/دانشکده/رشته/مقطع/گرایش/ورودی، مدیریت پیش‌نیاز و چارت، نشر/آرشیو/نسخه، بررسی موبایل، داده‌های ایرانی واقعی.
- **P0:** نقشهٔ درسی ترم‌به‌ترم و مسیر کل فارغ‌التحصیلی بر اساس تمام چارت؛ اطلاعات پاس‌شده، شرایط هر ترم و قواعد رسمی اثبات‌شده.
- **P1:** نظام اعتبارسنجی واقعی «بهترین استاد» با امتیازهای معنادار و شناسهٔ ثابت مدرس؛ تا آن زمان فقط ترجیح خود دانشجو مبناست و نباید رتبهٔ ساختگی نمایش داده شود.
- **P1:** توسعه جستجوی دقیق‌تر از beam محدود برای ترکیب‌های حجیم، جلسات چندروزه و درس‌های هم‌نیاز وابسته؛ اجتناب از وعدهٔ «بهینهٔ جهانی».
- **P0 مستقل:** تصمیم‌گیری مالک درباره «چارت معارف دانشگاه آزاد برای کارشناسی پیوستهٔ رشته‌های غیرپزشکی»؛ **قبل از توضیح و تأیید هیچ قاعدهٔ جدیدی اعمال نشود**.
