# دفتر دائمی درخواست‌ها و تصمیمات مالک درس‌چین

> **منبع عملیاتی و قابل ردیابی** برای تمام دستورها و پلن‌های محصول. این سند از ۲۰۲۶/۱۰/۲۵ آغاز شده و علاوه بر اسناد تخصصی نگهداری می‌شود؛ هدفش جلوگیری از فراموشی خواسته‌ها با عوض‌شدن چت، مدل، همکار یا محیط توسعه است. **ثبت خواسته ≠ پیاده‌سازی ≠ تأیید قانون آموزشی ≠ انتشار.**

## پروتکل ثبت (الزامی)

۱. پس از **هر دستور، تصمیم، اصلاح، اولویت، درخواست جدید، ایدهٔ پذیرفته‌شده یا باگ** از طرف مالک، یک ردیف تاریخ‌دار در این دفتر ثبت کنید؛ حتی اگر اجرای آن عقب افتاده باشد. اگر گفت‌وگو طولانی شد، همهٔ اجزای خواسته را تفکیک و لینک بدهید.

۲. شناسهٔ ثابت، موضوع، خلاصهٔ قابل‌آزمون، فوریت، وضعیت، سند تفصیلی، لینک PR/Issue و «سؤالات/وابستگی‌های باقی‌مانده» ضروری است. برای پروژه‌های بزرگ یک سند اختصاصی بسازید و از `docs/INDEX.md` پیوند دهید. هیچ نکتهٔ صرفاً شفاهی/داخل حافظهٔ دستیار را به‌عنوان مستند ثبت‌شده حساب نکنید.

۳. حالت‌های معتبر: `درخواست‌شده`، `طراحی‌شده`، `در حال توسعه`، `در PR و تست‌نشده`، `تست‌شده برای SHA مشخص`، `ادغام‌شده`، `در محیط واقعی تأییدشده`، `در انتظار تصمیم`، `جایگزین‌شده`. فقط با شواهد واقعی وضعیت را پیش ببرید؛ تست و Vercel را مستقل از یکدیگر گزارش کنید.

۴. وقتی تصمیم مالک با سند قدیمی تعارض دارد، **دستور جدید اولویت دارد** و باید سند قدیمی با علامت `Superseded` و ارجاع متقابل اصلاح شود؛ سوابق قدیمی را برای حسابرسی حفظ کنید.

۵. هیچ الزام یا جزئیات **آیین‌نامهٔ دانشگاهی** بدون تأیید روشن مالک و ثبت در [پروندهٔ قوانین آموزشی](ACADEMIC_RULES_INTAKE_FA.md) به سیاست قطعی تبدیل نمی‌شود. نیاز به پشتیبانی از نوع شرط، به معنی تصویب مقدار آن شرط نیست.

۶. فقط خلاصهٔ **غیرحساس** ثبت کنید. شماره شخصی، رمز، کلید، دادهٔ دانشجوی واقعی و اسناد محرمانه نباید در GitHub قرار بگیرد. اگر هنوز فایل در PR است، در گزارش عبارت «روی شاخه، هنوز نه در main» را صریح بگویید.

## OWN-040 — دو محیط مستقلِ تست و اصلی با الگوگیری فقط‌خواندنی از تکین (۲۰۲۶/۱۰/۲۶)

در ادامهٔ OWN-036 و OWN-038، مالک خواست کد دیپلوی شرکت تکین **فقط خوانده شود** و در صورت مفیدبودن، جداسازی انتشار آزمایشی و اصلی برای درس‌چین نیز پیاده شود؛ توسعه و رفع ایراد هم ادامه داشته باشد. **حق هیچ نوع تغییر در مخزن تکین وجود ندارد.**

- **هدف / معیار پذیرش:** staging و production از نظر data directory، user سرویس، secrets، مسیر release/current و پورت مستقل باشند؛ ابزار read-only با SHA کامل، خروجی Dry-run به‌عنوان حالت پیش‌فرض، کنترل JSON health/404 و الزام تست staging روی همان SHA قبل از تأیید production داشته باشد؛ localhost-only و fail-closed، بدون وابستگی اجباری به GitHub Actions.
- **پیش‌نیاز عملیاتی:** تست مستقل Bun/Vitest/Build/API smoke، بکاپ و restore واقعی دادهٔ درس‌چین، اطمینان از پایداری systemd، مجوز اپراتور و دامنه/TLS مستقل. Vercel Preview فعلاً تنها رابط کاربری است و Express را میزبانی نمی‌کند. PR #42 و crash-loop VPS هنوز جداگانه نیازمند بررسی هستند.
- **وضعیت:** قرارداد `deploy/targets.json`، سرویس نمونهٔ staging، فایل متغیرهای نمونه، گیت `deploy:gate` و تست‌های رجعتی در شاخهٔ `feat/staging-prod-release-gates-20261026` ثبت شده‌اند؛ **روی VPS نصب/اجرا نشده‌اند**. تست‌های مستقل ابزار گیت روی Sandbox با **۱۳/۱۳ آزمون Vitest** (از جمله listener واقعی با پورت تصادفی و جلوگیری از دسترسی production هنگام SHA نادرست staging) و بررسی TypeScript موفق شدند؛ یک آزمایش GET واقعی با دو listener ساختگی در loopback نیز الزام SHA یکسان را نشان داد. گیت کامل برنامه برای این SHA مستقل دوباره اجرا نشده (آخرین گیت کامل مربوط به PR #34 و mainِ پیش از این شاخه است)؛ وضعیت مرج و انتشار باید جدا گزارش شود.

## OWN-041 — الگوبرداری کلی از معماری تکین و مدرن‌ترشدن درس‌چین (۲۰۲۶/۱۰/۲۶)

مالک مجدداً تأکید کرد کل معماری تکین صرفاً برای **بررسی/الهام** قابل مطالعه است، اما درس‌چین باید رابط، فناوری و ساختار مستقل، مدرن‌تر و مناسب موبایل داشته باشد؛ **هیچ تغییر یا PR/Issue در مخزن تکین مجاز نیست**. این تصمیم ادامهٔ OWN-040 و اولویت UX/معماری قبلی است و هدف عرضهٔ قابل‌اعتماد نیازسنجی را عقب نمی‌زند.

- **تصمیم فنی:** مهاجرت نمایشی از React/TypeScript/Vite/Express ممنوع نیست، اما بدون دادهٔ عملکردی و نیاز ثابت توجیه ندارد. فعلاً از الگوهای معماری سرویس‌ها، middleware امنیتی، توکن‌های UI و مسیر استقرار مستقل از تکین الگوبرداری می‌شود.
- **پیاده‌سازی فاز A:** امنیت HTTP مرکزی، ErrorBoundary قابل‌بازیابی، skeleton route-level، skip-link و responsive container query با رعایت reduced motion؛ آزمون‌های رفتاری مرتبط اضافه شده‌اند.
- **گام‌های باز:** تفکیک feature-based پنل‌ها، API typed schema، بهبود واقعی پنل نیازسنجی و مدیریت، تست تصویری responsive، performance budget، audit CSP و مطالعهٔ database transactional. هیچ قانون آموزشی بدون مجوز صاحب پروژه تغییر نکند.
- **وضعیت:** تغییرات فاز A ابتدا روی شاخهٔ `feat/modern-foundations-resilience-20261026` قرار دارد؛ **مرج/بیلد/استقرار فقط پس از ثبت شواهد مستقل تأیید می‌شود**.
