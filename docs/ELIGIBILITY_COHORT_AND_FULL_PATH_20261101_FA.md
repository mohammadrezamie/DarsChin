# انطباق چارت دانشجو و اهمیت دروس باقی‌مانده — ۱ نوامبر ۲۰۲۶

## ایراد و دامنهٔ اصلاح

پیش‌تر ارزیابی در صورت نیافتن چارت با دانشگاه/رشته/ورودی، به اولین چارت موجود در دیتابیس رجوع می‌کرد؛ تفاوت واحد و مقطع و نسخهٔ پیش‌نویس نیز در تطبیق اولیه لحاظ نمی‌شد. این باعث امکان تحلیل بر اساس چارت **دانشجوی دیگر** می‌شد. ارائه‌های درسی نیز فقط با نیمسال پالایش می‌شدند و نه واحد دانشجو. موتور پیشنهاد به‌صورت پیش‌فرض دانشجو را «ترم سوم» فرض می‌کرد، حتی اگر چنین داده‌ای در پرونده وجود نداشت.

## رفتار اصلاح‌شده

- API فقط **یک چارت فعال** را می‌پذیرد که دانشگاه، واحد، مقطع، رشته و ورودی آن دقیقاً با پروفایل منطبق باشد. صفر نتیجه یعنی پیام قابل‌فهم برای تکمیل/اصلاح چارت؛ بیش از یک چارت فعال یعنی خطای تعارض و لزوم تعیین نسخهٔ معتبر. هیچ انتخاب دلخواه از اولین رکورد یا اعمال چارت پیش‌نویس وجود ندارد.
- درس‌های ارائه‌شده تنها از همان نیمسال معتبر و همان واحد دانشگاهی دانشجو بررسی می‌شوند؛ نیمسال نمونهٔ ثابت جایگزین دادهٔ نامعتبر نمی‌شود.
- خروجی ارزیابی خصوصی با `Cache-Control: no-store` محافظت می‌شود.
- اهمیت دروس همچنان از زنجیرهٔ پیش‌نیاز **تا پایان چارت** محاسبه می‌شود، اما دروس پاس‌شدهٔ قطعی از شمار «دروس آینده» کسر می‌شوند؛ وضعیت FAILED/ABSENT یا نمرهٔ مردودی به‌عنوان پاس‌شده فرض نمی‌شود.
- دیگر بدون اطلاعات معتبر، موقعیت «ترم سوم» به دانشجو نسبت داده نمی‌شود. رتبه‌بندی فقط نشانهٔ تحلیلی برای برنامه‌ریزی است و حکم مجوز انتخاب واحد دانشگاه نیست.

## مرزها و تست پذیرش

تست HTTP با کاربران مصنوعی، رد چارت ورودی دیگر، رد واحد/مقطع نامنطبق، رد draft و چند چارت فعال، حذف ارائهٔ واحد دیگر و نیمسال نامعتبر؛ تست مستقل اولویت مسیر تا فارغ‌التحصیلی، حذف دروس گذرانده از تاثیر زنجیره و عدم استفاده از ترم فرضی.

تا دریافت توضیح و تأیید صریح مالک، **هیچ قانون جدید مربوط به معارف دانشگاه آزاد برای کارشناسی پیوستهٔ رشته‌های غیرپزشکی** اعمال نشده است. تغییرات صرفاً دربارهٔ انتخاب دقیق چارت و نمایش شاخص‌های موجود است؛ محتوا/مقررات واقعی چارت همچنان نیازمند تأیید آموزشی است.
