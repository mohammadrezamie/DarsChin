# دامنهٔ مستقل درس‌چین روی VPS مشترک با تکین (بدون دستکاری تکین)

**پاسخ کوتاه: بله.** یک VPS می‌تواند چند دامنه با برنامه‌های جدا داشته باشد. مالکیت دامنه‌ها، دیتابیس‌ها، محیط‌ها، پورت‌های داخلی، سرویس‌ها و گواهی‌ها مستقل‌اند. خرید دامنه به معنی خرید سرور تازه نیست.

## ۱. معماری پیشنهادی برای VPS فعلی

```text
                     اینترنت ایران و جهان
                            |
                     IP عمومی VPS مشترک
                            |
                   Nginx فعلی :80/:443
                    /                   \
         takin.example.ir          darschyn.example.ir
         Takin: PHP/Laravel        DarsChin: Node/Express
         upstream فعلی             127.0.0.1:3001
                    \                   /
                  محیط‌ها/فایل‌ها/دیتابیس مستقل
```

- DNS `A` برای دامنه درس‌چین به همان IPv4 سرور؛ اگر IPv6 واقعاً فعال است `AAAA` هم تنظیم شود. رکوردهای تکین را تغییر نده.
- **Nginx موجود** را به‌عنوان تنها ورودی عمومی ۸۰/۴۴۳ حفظ کن؛ فایل virtual host درس‌چین جدا تعریف شود (نمونه `deploy/nginx-darschyn.conf.example`). اگر تکین قبلاً از Nginx استفاده می‌کند، با دستور `docker compose ... up` **کل استک Caddy را اجرا نکن**؛ چون دو سرویس نمی‌توانند همان پورت‌ها را بگیرند.
- درس‌چین را پشت یک پورت فقط-محلی مانند `127.0.0.1:3001` قرار بده؛ چنانچه ۳۰۰۱ هم اشغال است، از یک پورت آزاد استفاده کن. پورت داخلی کانتینر همچنان ۳۰۰۰ است.
- فایل‌ها، env خصوصی، بکاپ، volume و کاربر سیستم از تکین مستقل باشند. **هیچ دستور نصب/حذف در پوشهٔ تکین اجرا نمی‌شود.**
- Nginx باید `Host` واقعی را به Express پاس دهد. بعد از DNS، گواه TLS دامنهٔ جدید را با همان ابزار صدور گواه فعلی سرور فعال کن. وضعیت HTTPS و سایت تکین را **قبل و بعد** بررسی کن.

## ۲. راه‌اندازی مرحله‌ای، اول امن و داخلی

روی سرور (تنها در checkout مربوط به درس‌چین و بعد از آماده‌کردن فایل خصوصی `deploy/.env.vps`):

```bash
sudo ss -lntp | grep -E ':(80|443|3000|3001)\\b' || true
# در deploy/.env.vps مقدار DARSCHYN_LOCAL_PORT=3001 و اسرار اختصاصی را قرار بده
docker compose -f compose.yaml -f compose.pilot-ssh.yaml --env-file deploy/.env.vps config -q
docker compose -f compose.yaml -f compose.pilot-ssh.yaml --env-file deploy/.env.vps up -d --build darschin
curl -fsS http://127.0.0.1:3001/api/health
```

در این حالت **فقط سرویس `darschin` بالا می‌آید**، نه proxy/Caddy. بعد می‌توانی از لپ‌تاپ با تونل SSH آزمایش کنی:

```bash
ssh -L 3001:127.0.0.1:3001 USER@VPS_IP
```

و `http://localhost:3001/demo/student` را باز کنی. تا وقتی TLS عمومی آماده نیست، فرم حساب واقعی را از اینترنت عمومی تست نکن.

## ۳. فعال‌کردن دامنهٔ مستقل در Nginx

1. دامنه جدا بخر (پسوند به انتخاب خودت؛ مثلاً .ir یا .com). آزادبودن یا قیمت نام مشخص قبل از خرید باید از ثبت‌کننده بررسی شود.
2. DNS آن را به همان VPS اشاره بده؛ گواه و فعال‌شدن DNS چند دقیقه تا چند ساعت بسته به TTL طول می‌کشد؛ زمان دقیق تضمین نمی‌شود.
3. نمونهٔ virtual host موجود را **در فایل جدید** مخصوص درس‌چین کپی کن و آدرس upstream را از 3000 به `3001` و `server_name` را به دامنهٔ خریداری‌شده تغییر بده.
4. قبل از فعال‌کردن یا بارگذاری مجدد، `sudo nginx -t` اجرا کن و از تنظیم فعلی پشتیبان بگیر. اگر خطا دارد reload نکن.
5. گواه HTTPS جدید را با روش رایج همین Nginx ایجاد کن؛ سپس `curl -I https://YOUR_DARSCHYN_DOMAIN/` و `curl -I https://TAKIN_EXISTING_DOMAIN/` هر دو باید سالم باشند.
6. نام دامنهٔ جدید را در `TURNSTILE_ALLOWED_HOSTNAMES` هم قرار بده و کلید کپچا را فقط برای همان hostname بساز.

**مهم:** VPS مشترک امنیت و پایداری را به هم وابسته می‌کند (خرابی دیسک، کمبود RAM/CPU، قطعی شبکه). برای استفادهٔ سراسری دانشگاه، بعداً منابع و جداسازی فیزیکی باید دوباره ارزیابی شوند. در پایلوت فقط فرآیند تک‌فرایندی مجاز است؛ دیتابیس JSON برای چند replica مناسب نیست.

## ۴. از کدام دستورها اجتناب شود؟

- `docker compose up -d` با سرویس Caddy در زمانی که Nginx تکین مالک 80/443 است.
- اجرای دو سرویس روی پورت میزبان یکسان یا bind کردن Node به `0.0.0.0:3001`.
- اجرای `rm -rf`، `git clean` یا `reset` در مسیر تولید تکین یا درس‌چین.
- استفادهٔ مشترک از `.env`، JWT، کلید نیازپرداز، بکاپ یا پایگاه‌دادهٔ هر دو محصول.
- تبلیغ نسخه به‌عنوان آمادهٔ دریافت اطلاعات واقعی دانشجو قبل از تست SMTP/SMS، ثبت‌نام، مجوزها، پشتیبان و بازیابی.

## ۵. روش مستقل در آینده

اگر VPS خالی و تنها برای درس‌چین باشد، `compose.yaml` به‌همراه Caddy می‌تواند خودش HTTPS را مدیریت کند؛ اگر **روی همان VPS تکین** میزبانی می‌کنی، Nginx فعلی + فقط سرویس درس‌چین مناسب‌تر و کم‌ریسک‌تر است.
