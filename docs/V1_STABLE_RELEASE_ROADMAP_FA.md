# نقشهٔ راه انتشار پایدار درس‌چین ۱.۰

**تصمیم مالک — ۶ آذر ۱۴۰۵ | OWN-V1-STABLE-028**: تمام کارهای لازم تا انتشار نسخهٔ یک پایدار به Issue تبدیل شوند و مرحله‌به‌مرحله با آزمون و پذیرش واقعی تکمیل شوند.

[پروندهٔ مادر انتشار #150](https://github.com/mohammadrezamie/DarsChin/issues/150) مرجع زندهٔ وضعیت، وابستگی‌ها، پذیرش و اولویت است. این سند قرارداد ثابت است؛ وضعیت لحظه‌ای را از Issue و SHA واقعی بخوانید. هنگام ثبت اولیه، ۱۰ Issue جدید به ۱۶ Issue باز قبلی متصل شدند. هیچ Issue به دلیل نوشتن این سند تکمیل‌شده نیست.

## محدودهٔ پیشنهادی نسخهٔ پایدار

نسخهٔ ۱.۰ باید در دامنهٔ دانشگاه/رشته/مقطع/ورودی تأییدشده واقعاً قابل استفاده باشد: ورود و ثبت‌نام امن، چارت و قوانین نسخه‌دار، برنامه‌ریز دانشجو، پنل مدیر، نیازسنجی، الگوچین، ورود دادهٔ معتبر، رابط حرفه‌ای و دسترس‌پذیر، دادهٔ پایدار، بکاپ و استقرار قابل بازگشت. این تعیین محدوده یک پیشنهاد فنی است و جای تأیید مالک برای دامنهٔ عرضه یا قواعد دانشگاهی را نمی‌گیرد. اتصال مستقیم معیار فقط با مجوز و قرارداد معتبر؛ مسیر دستی امن مستقل لازم است. قابلیت ضروری فقط با تصمیم صریح مالک از نسخه خارج شود.

## قرارداد پذیرش و گزارش پیشرفت

- هر Issue معیار پذیرش مستقل، PR مرتبط، SHA دقیق، نتیجهٔ مثبت/منفی و محدودیت‌های باقی‌مانده دارد. برای مسائل همپوشان، شاهد مشترک ارجاع شود؛ بدون اثبات همهٔ معیارها Issue بسته نشود.
- کارهای تست به‌صورت جامع و موازی انجام شوند؛ گیت تجمیعی تنها پس از موفقیت همهٔ مراحل پذیرفته شود. شواهد تست مصنوعی از آزمون زندهٔ مرورگر، ارائه‌دهنده و سرور جدا هستند. اسناد و برنامهٔ انتشار به‌روز بمانند.
- پیشرفت با تعداد Issueهای پذیرفته‌شده، مانع‌های P0 و وضعیت نامزد انتشار گزارش شود؛ تعداد Issue بسته‌شده معادل درصد آمادگی یا پوشش کد نیست.
- پیش از انتشار، نسخهٔ ثابت RC با آزمون کامل، پایلوت محدود، تأیید مقررات و دامنهٔ داده، بررسی امنیت، تمرین Restore و rollback، مجوز جداگانهٔ استقرار و شواهد سلامت پذیرفته شود. هیچ برچسب Stable یا Tag نسخهٔ ۱.۰ پیش از این مرحله ایجاد نشود.
- هیچ دادهٔ واقعی دانشجو، Secret یا لاگ حساس وارد GitHub نشود؛ VPS فعلی و تکین بدون مجوز مستقل تغییر نکنند. توسعهٔ امکانات نسل بعدی جداگانه دنبال شود و نباید انتشار امن را به تأخیر بیندازد.
