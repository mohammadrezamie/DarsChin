# جریان یکپارچهٔ انتخاب درس، استاد و صف ثبت

**درخواست مالک ـ ۲ نوامبر ۲۰۲۶ | وضعیت: تغییرات در PR، انتشار پس از تست و تأیید**

## رفتار صحیح و واحد

۱. دانشجو ابتدا فقط **درس‌های مورد نظر** را از چارت تحصیلی در مرحله «انتخاب درس‌ها» برمی‌گزیند. در این مرحله نیازی به انتخاب استاد یا گروه نیست و انتخاب به‌تنهایی اخذ رسمی نیست.

۲. در مرحله دوم، برای **هر درس منتخب** استاد و گروه انتخاب اول و سپس گروه‌های جایگزین (اولویت دوم، سوم و ...) تعیین می‌شوند. گزینه نامجاز باید همراه با دلیل غیرفعال باشد. انتخاب استاد اول نباید بدون دستور دانشجو انجام شود.

۳. **اولویت درس‌ها و جایگزین‌ها بخشی از همان صف ثبت هستند**: صف سریع ثبت بر اساس برنامه و اولویت ذخیره‌شده مرتب می‌شود و گروه‌های جایگزین را داخل همان ردیف درس نشان می‌دهد. دو مدل متفاوت برای «چینش» و «صف ثبت» ساخته نشود. جابه‌جایی اولویت درس‌ها از صف ثبت، جابه‌جایی جایگزین‌ها از همان بخش مشترک انجام می‌شود.

۴. جدول هفتگی و تقویم امتحان جدا به‌عنوان نمای اطلاعاتی باقی می‌مانند؛ بخش ویرایش مستقل و تکراریِ اولویت‌ها از این نما برای دانشجو پنهان شده است. مسیر `wishlist` سابق برای سازگاری با لینک‌های قدیمی حفظ می‌شود، ولی ناوبری اصلی یک روند واحد دارد.

۵. هیچ گروه موجود در برنامهٔ قبلی با تغییر سبد علاقه‌مندی خودکار حذف نمی‌شود؛ وجود موارد قبلی خارج از فهرست فعلی باید هشدار داده شود تا دانشجو بدون از دست رفتن داده تصمیم بگیرد. تمام تغییرات برنامه همچنان از API سروری و اعتبارسنجی قبلی عبور می‌کنند؛ دمو صرفاً ساختگی و بدون ثبت خودکار در آموزشیار است.

## بازطراحی رنگ‌ها

رنگ‌بندی جدید زنده و صمیمی است: بنفش و ارغوانی برای عملیات اصلی، آبی فیروزه‌ای برای اطلاعات، نارنجی ملایم برای گزینه‌های ثانویه، سبز برای موفقیت و قرمز برای خطا. رنگ معنادار هشدار/مجوز مخدوش نشود؛ خوانایی RTL، حالت تاریک، موبایل و ترجیح کاهش حرکت حفظ شوند. این تغییر شامل صفحهٔ اصلی، هویت بصری مشترک و جریان جدید ثبت است؛ زیرساخت، سرور و قواعد آموزشی دست‌نخورده می‌مانند.

## گیت کیفیت

`bun run verify`، بررسی پیش‌نمایش استاتیک و API دمو، تست مسیر course-first، هشدار تداخل، ذخیرهٔ جایگزین و نمایش موبایل/حالت تاریک باید روی کامیت دقیق PR تأیید شوند؛ موفقیت تست خودکار جای مشاهده مرورگری را نمی‌گیرد.

## محدودیت انتشار

GitHub Pages تنها پس از انتشار موفق workflow دستی محتوای `main` را منعکس می‌کند و دیپلوی Vercel مستقل است. فایل در PR به‌معنای حضور در سایت لایو نیست.
