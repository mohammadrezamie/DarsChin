# اجرای مستقل گیت کیفیت درس‌چین بدون GitHub Actions

**ثبت شده در ۲۰۲۶/۱۰/۲۶ — وضعیت:** روش اجرایی آزمایش شده؛ اجرای نهایی هر PR باید جداگانه ثبت شود.

این مسیر به GitHub Actions، سرور اصلی، دیتابیس واقعی یا سرویس تکین وابسته نیست. ابزار مرجع پروژه **Bun 1.4.4**، Node.js 22+، TypeScript، Vitest، Vite و API smoke ایزوله است.

## تنها فرمان مورد نیاز

بعد از clone مخزن خصوصی و checkout دقیق SHA مورد آزمایش، در PowerShell ویندوز، macOS یا Linux:

```sh
bun install --frozen-lockfile
bun run qa:full
```

`qa:full` به‌ترتیب `bun run verify` و `bun run smoke:api` را اجرا می‌کند و اگر یکی از مرحله‌ها شکست بخورد، exit code غیرصفر می‌دهد. `verify` نسخه‌های قفل‌شده را کنترل و TypeScript، تمام Vitestها و بیلد production را اجرا می‌کند؛ runner برای آزمون‌ها credentialهای **کاملاً مصنوعی** و `DARSCHYN_DATA_DIR` ایزوله تولید می‌کند. `smoke:api` سرور ساخته‌شده را با دیتای موقت می‌آزماید.

نحوهٔ ثبت نتیجهٔ قابل حسابرسی در PR:

```sh
git rev-parse HEAD
bun --version
bun run qa:full
git status --short
```

صرفاً **SHA دقیق، خروجی نهایی و وضعیت فایل‌های تغییرکرده** را گزارش کنید؛ credentialها، JWT، دادهٔ خصوصی، ENV، پوشهٔ دیتابیس موقت یا لاگ حاوی اطلاعات محرمانه را منتشر نکنید. خروجی ساخته‌شدهٔ ZIP افزونه نباید ناخواسته commit شود.

## گزینهٔ ابری برای توسعه‌دهنده یا دستیار متصل

از **Vercel Sandbox** برای اجرای همان `qa:full` در یک VM موقتِ جداگانه از Production استفاده کنید. در تست ۲۰۲۶/۱۰/۲۶، GitHub private از sandbox با `git clone` ساده قابل دسترسی نبود؛ دستیار از GitHub plugin، فایل‌های متن منبع را با کنترل تک‌به‌تک `git hash-object` منتقل کرد و وابستگی‌ها با `bun install --frozen-lockfile` نصب شدند. هیچ توکن GitHub/Password در sandbox قرار نگرفت. هر sandbox تازه باید **آخرین SHA** را دوباره دریافت و تأیید کند؛ یک build قدیمی Vercel شاهد اجرای SHA جدید نیست.

**محدودیت همان اجرای اولیه:** در کپی برنامه‌ای سورس به Sandbox، سه فایل binary `woff2` منتقل نشده بودند؛ بنابراین Vite برای مسیرهای فونت سه هشدار `didn't resolve` تولید کرد، اما بیلد exit code صفر داشت. این هشدارها مربوط به محیط کپی ناقص است؛ وجود فایل‌ها در مخزن GitHub بررسی شده و مرورگرِ واقعیِ خروجی روی فونت همچنان باید آزمون شود. موفقیت تست در محیط ناقص را به‌عنوان موفقیت آزمایش همهٔ فایل‌های باینری و ویوپورت‌ها گزارش نکنید.

## نتایج اجرای ایزولهٔ اولیه — ۲۰۲۶/۱۰/۲۶

- اولین `bun run lint` روی PR #34 دو خطای TS2339 در `StudentDashboard.tsx` پیدا کرد؛ با تبدیل `Array.from(NodeList || [])` به `NodeListOf<HTMLButtonElement>` اصلاح شد و **TypeScript بدون خطا پاس شد**.
- اجرای اولیهٔ Vitest شکست دو تست قدیمی CSS/صف ثبت و نیاز به credential آزمایشی JWT را آشکار کرد. دو تست/کنترل اصلاح شدند و پس از تنظیم متغیرهای **موقت** آزمایشی، `44/44` فایل و `224/224` تست Vitest پاس شدند.
- `bun run build`: **موفق** (با هشدار فونت در محیط انتقال ناقص).
- `bun run smoke:api`: **موفق**؛ از جمله health، JSON 404، ورود ساختگی، API خصوصی نیازسنجی، حفاظت reset در production و پایداری sync، همگی روی پوشهٔ دادهٔ موقت.
- `bun run verify`: **موفق** شامل frozen install، TypeScript، Vitest و بیلد.
- شواهد این مراحل مربوط به سورس PR #34 در حین رفع تست است. SHA نهایی و آخرین `qa:full` باید **در خود PR** ثبت شود.

## شرط مرج

PR تنها وقتی قابل مرج است که (۱) آخرین head SHA بررسی و از `main` عقب نباشد؛ (۲) گیت کامل شامل API smoke روی همان سورس اجرا و exit code صفر داشته باشد؛ (۳) diff برای اطلاعات حساس و تغییرات خارج از scope بازبینی شود؛ (۴) تست‌های تعاملی/بصری ضروری متناسب با خطر تغییر صادقانه ثبت شوند؛ (۵) GitHub branch protection اجازه دهد. **PRهای مستقل مثل نیازسنجی #37 یا عملیات VPS #42 بدون اجرای جداگانهٔ gate خودشان از موفقیت PR #34 مجوز مرج نمی‌گیرند.**

گیت محلی «پاس» به معنی آماده‌بودن Production، اثبات دادهٔ آموزشی رسمی، بررسی همهٔ اندازه‌های موبایل یا حل حادثهٔ VPS نیست.
