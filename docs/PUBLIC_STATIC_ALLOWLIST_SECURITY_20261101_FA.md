# مسدودسازی دانلود مستقیم فایل‌های غیرمجاز افزونه و محیط آزمایشی — ۱ نوامبر ۲۰۲۶

**اصلاح امنیتی P0 در محیط Public، بدون تغییر در VPS موجود**

## مشکل

نسخهٔ قبلی ZIP افزونه را فقط با فهرست `extension/public-files.json` می‌ساخت، ولی همان سرور دو مسیر `/extension-files` و `/mock-portal-static` را با `express.static(...)` روی **کل پوشه** باز گذاشته بود. اگر در مسیر نصب نسخهٔ جدید فایل ناخواستهٔ `private.key`، `database.json`، نسخهٔ پشتیبان، خروجی build یا فایل حساس مشابه وجود داشت، HTTP مستقیم می‌توانست آن را خارج از ZIP و بدون احراز هویت ارسال کند. `dotfiles:'deny'` جلوی `private.key` یا `backup.json` را نمی‌گیرد؛ پس اتکا به آن کافی نیست.

## قرارداد جدید

- **افزونه:** فقط همان نام‌هایی که به شکل صریح در `extension/public-files.json` ثبت شده‌اند، از `/extension-files/<file>` قابل دریافت‌اند. خود `public-files.json`، فایل‌های تازه/اضافی، dotfileها، فایل‌های پشتیبان و لینک‌های غیرمجاز پاسخ `404` می‌گیرند.
- **دموی سامانهٔ آموزشی:** فقط `index.html` و نشانی ریشهٔ دموی قبلی `/mock-portal-static/` مجاز است. فایل‌های مجاور مجوز انتشار نمی‌گیرند.
- **فرار از مسیر:** gate مستقل با بررسی مسیر واقعی filesystem، نوع فایل و symlinkهای واسط (مانند `icons` یا `fonts`) فقط فایل Regular داخل ریشهٔ حقیقی مجاز را عبور می‌دهد.
- **ZIP مستقل:** منطق تولید ZIP در Backend و اسکریپت انتشار نیز symlink واسطِ خارج‌شونده از ریشه را رد می‌کند.
- **تست:** در `tests/approved-static-asset-gates.test.ts` درخواست‌های واقعی HTTP به فایل‌های مجاز، `private.key`، `.env`، `database.json`، فایل‌های اضافی در fonts/icons، symlink به بیرون و صفحهٔ مجاز محیط آزمایشی اجرا می‌شوند. تست منبع تضمین می‌کند هر دو guard واقعاً در `server.ts` قبل از static نصب شده باشند.

**محدودیت‌ها:** این کار دسترسیِ فعلی به تاریخچهٔ PR/GitHub refs یا فایل‌هایی که قبلاً منتشر شده‌اند را پس نمی‌گیرد. جابه‌جایی سرور، اعتبارنامه‌های قدیمی و بررسی Secret Scanning/Rulesets همچنان در [چک‌لیست مالک](OWNER_SECURITY_ACTION_CHECKLIST_FA.md) و [Issue #4](https://github.com/mohammadrezamie/DarsChin/issues/4) باز است. به سرور فعلی یا اتصال فعلی GitHub دست نزنید.
