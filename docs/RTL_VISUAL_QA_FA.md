# راهنمای بصری و تست RTL درس‌چین (پایلوت فارسی)

> نسخهٔ طراحی: ۱۴۰۵/۰۸/۰۳ (۲۵ اکتبر ۲۰۲۶)؛ **وضعیت: تغییرات در `main` ثبت شده، آزمون تصویری در مرورگر و موبایل واقعی هنوز در انتظار اجراست.**

## ۱. قرارداد طراحی — زبان فارسی و راست‌به‌چپ

- تمام صفحه‌های محصول، فرم‌ها، لیست‌ها، کارت‌های مدیریتی و پیام‌ها به‌صورت راست‌به‌چپ (`lang="fa" dir="rtl"`) چیده و متن فارسی راست‌چین می‌شود. متن وسط‌چین پیش‌فرض برای عناوین، پیام خطا، فرم‌ها و گزارش‌ها مناسب نیست.
- جهت چپ‌به‌راست **فقط برای محتوای ذاتاً LTR** مجاز است: شماره تلفن، ایمیل، URL، ساعت و رشته‌های کد. برچسب و موقعیت کنترل آن همچنان در چیدمان RTL می‌ماند.
- فونت محصول **Vazirmatn محلی** با فایل WOFF2 موجود در مخزن است؛ لود شدن آن در ایران نباید به Google Fonts یا CDN وابسته باشد. اندازهٔ ورودی متنی موبایل باید دست‌کم ۱۶px باشد تا Safari هنگام فوکوس زوم ناخواسته نکند.
- مقیاس بصری: کادرهای گرد ۱۲–۲۰px، فاصلهٔ قابل‌پیش‌بینی ۸/۱۲/۱۶/۲۴px، سطح سفید/سرمه‌ای متناسب با روز/شب، متون اصلی پرکنتراست و توضیحات فرعی با کنتراست مناسب.
- کنترل‌های قابل لمس حداقل ۴۴px، **فوکوس صفحه‌کلید قابل رؤیت**، حالات غیرفعال مشخص و عدم برش متن فارسی. ترجیح کاهش حرکت سیستم (`prefers-reduced-motion`) باید در انیمیشن‌ها رعایت شود.
- منوی موبایل از **سمت راست** وارد می‌شود، اسکرول پس‌زمینه قفل و با Escape/کلیک روی پس‌زمینه/بستن منو بسته می‌شود. فوکوس داخل منوی باز محصور می‌ماند و پس از بستن به دکمهٔ بازکننده بازمی‌گردد.

## ۳. ماتریس بازبینی دستی در مرورگر

| عرض viewport | انتظار |
| --- | --- |
| **۳۲۰px** | بدون اسکرول افقی کل صفحه؛ تب دانشجو تک‌ستونه، ورود و دمو قابل لمس، منو قابل بستن |
| **۳۷۵px** | هدر و انتخاب تم بدون شکست، فرم شماره تماس بدون zoom ناخواسته |
| **۳۹۰px / ۴۳۰px** | دو ستون در تب‌های دانشجو، مجوزهای مدیر قابل خواندن، CTAها بدون بریدگی |
| **۷۶۸px** | فرم‌ها با ستون‌های منطقی؛ جدول‌های مدیریت قابل استفاده و بدون اسکرول عمودی غیرعادی |
| **۱۰۲۴px** | سایدبار سمت راست مدیریت، ناوبری کامل و خوانا |
| **۱۴۴۰px** | کارت‌ها و سرفصل‌ها تناسب داشته باشند؛ ستون‌ها بیش از حد پهن نشوند |

برای **هر عرض** این حالت‌ها را بررسی کن: روز، شب، خودکار (هم سیستم روشن هم سیستم تاریک)، افزایش اندازهٔ متن مرورگر به ۲۰۰٪، زوم صفحه تا ۲۰۰٪، صفحه‌کلید فقط با Tab/Shift+Tab/Escape، prefers-reduced-motion، مرورگر Safari آیفون و Chrome اندروید.

### سناریوها — از مسیر اصلی دمو

1. `/`: منوی همبرگری در راست، لوگو/متن فارسی در راست، دکمه‌های دموی بدون ورود؛ اسکرول صفحه هنگام بازبودن منو قفل باشد.
2. `/login`، `/register`، `/forgot-password`: برچسب‌ها و متن‌ها راست‌چین، ورودی شماره/رمز قابل استفاده، فوکوس پیدا و خطاها خوانا.
3. `/demo/student`: هدر اکشن‌ها، همهٔ ۷ تب، نمایش داده‌های طولانی فارسی و تغییر روز/شب.
4. `/demo/student` → **برنامهٔ هفتگی**: روزها را با تب انتخاب کن، جدول ۷–۲۰ را ببین، هم‌پوشانی کلاس‌ها و کلاس بی‌زمان مشخص باشد.
5. `/demo/admin`: منوی بخش‌ها در راست، جست‌وجوی بخش‌ها، فرم افزودن/ویرایش و جداول کارت‌دار موبایل.
6. `/demo/admin?tab=users`: نقش‌ها، مجوزها، چک‌باکس‌ها و تعیین محدودهٔ مدیر گروه، بدون جدول ریز و غیرقابل لمس.
7. `/demo/admin?tab=demand` و `/demo/student` → نیازسنجی: فرم طولانی و انتخاب دروس بدون برش یا چسبیدن دکمه‌ها.
8. `/demo`: دمو برنامه‌ریز و زمان‌بندی، تم روز/شب، کادرهای درس و پیام خطا.
9. نماهای Modal، وضعیت خالی و loading، خطا، toast/alert و صفحهٔ مرورگر در فونت بزرگ را جدا بازبینی کن.

## ۴. نشانه‌گذاری باگ بصری

هر گزارش باگ باید شامل: مسیر صفحه، عرض × ارتفاع viewport، مرورگر و نسخه، حالت تم، مرحلهٔ بازتولید، تصویر قبل/بعد (بدون اطلاعات واقعی دانشجو)، نوع مشکل (RTL/فونت/فاصله/کادر/رنگ/انیمیشن/فوکوس/overflow)، شدت P0–P3 و **Git commit SHA** نسخهٔ تست‌شده باشد.

نمونه: «`/demo/admin?tab=users`، ۳۲۰×۷۲۰، Safari، شب، چک‌باکس مجوزها از کادر بیرون زده، P1».

## ۵. دروازهٔ انتشار

`bun run lint && bun run test && bun run build` و آزمون مرورگر در عرض‌های بالا باید روی SHA نهایی موفق شود. تغییر فایل و وجود تستِ منبع **به‌تنهایی معادل صحت بصریِ تأییدشده نیست**. استقرار Vercel که SHA قدیمی دارد، نباید نسخهٔ آخر معرفی شود. هیچ دادهٔ شخصی واقعی برای آزمون UI لازم نیست.
