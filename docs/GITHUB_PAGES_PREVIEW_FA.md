# پیش‌نمایش فقط‌نمایشی درس‌چین روی GitHub Pages

**وضعیت:** آماده‌سازی کد و گردش کار؛ فعال‌شدن Pages و موفقیت اجرای واقعی باید جداگانه بررسی شوند.

## محدوده و ایمنی

این انتشار از نسخهٔ تأییدشدهٔ `main` فقط فایل‌های خروجی فرانت‌اند Vite را در GitHub Pages قرار می‌دهد. حالت `VITE_STATIC_PREVIEW=true` مسیریابی را به HashRouter تغییر می‌دهد، API واقعی را غیرفعال می‌کند و فقط از پاسخ‌های ساختگی مرورگر در دمو استفاده می‌کند. دادهٔ واقعی دانشجویان، دیتابیس، ENV، JWT، پیامک و سرور Express نباید در این محیط حاضر باشند. پنل مدیر در این نسخه صرفاً شبیه‌سازی با هویت ساختگی است و هیچ دسترسی واقعی به سرور ایجاد نمی‌کند.

- صفحهٔ اصلی: `https://mohammadrezamie.github.io/DarsChin/`
- دموی دانشجو: `https://mohammadrezamie.github.io/DarsChin/#/demo/student`
- دموی مدیر ساختگی: `https://mohammadrezamie.github.io/DarsChin/#/demo/admin`
- برنامه‌ریز آزمایشی: `https://mohammadrezamie.github.io/DarsChin/#/demo`

این لینک‌ها **تا قبل از اولین اجرای موفق و فعال‌سازی Pages، فعال محسوب نمی‌شوند**.

## فعال‌سازی اولیه (نیازمند دسترسی صاحب ریپو)

۱. در گیت‌هاب به `DarsChin → Settings → Pages` بروید و در `Build and deployment → Source` گزینهٔ **GitHub Actions** را انتخاب کنید.

۲. در تب `Actions` گردش کار «انتشار دستی پیش‌نمایش درس‌چین در Pages» را انتخاب کنید، `Run workflow` را روی شاخهٔ `main` بزنید.

۳. بعد از موفقیت گردش کار، لینک دموی دانشجو و مدیر را در موبایل بررسی کنید؛ **صرف موفقیت بیلد به‌معنی تأیید UX نیست**. مسیرهای HashRouter از شکست refresh در سرور استاتیک جلوگیری می‌کنند.

۴. برای به‌روزرسانی بعدی **فقط در صورت نیاز** همین گردش کار را دستی اجرا کنید. این روند روی هر push اجرا نمی‌شود تا از مصرف بیهودهٔ دقیقه‌های GitHub Actions جلوگیری شود. این بیلد جایگزین تست‌های امنیتی، TypeScript، Vitest، بک‌اند و استقرار واقعی نیست.

## ساخت محلی

پس از `bun install --frozen-lockfile` فرمان `node scripts/build-pages-preview.mjs` را اجرا کنید. تنها محتوای پوشهٔ `dist/` باید منتشر شود؛ هرگز ریشهٔ ریپو، `data/`، فایل‌های `.env`، `deploy/` یا `server/` را آپلود نکنید.

## بازگشت

برای توقف نمایش عمومی، در `Settings → Pages` انتشار را غیرفعال کنید. برای بازگرداندن کد، PR مربوط را Revert کنید؛ به استقرار واقعی یا اتصال فعلی VPS دست نزنید.
