# ساختار و نظافت مخزن درس‌چین

## اصل
مخزن باید هم برای توسعهٔ مرحله‌ای و هم نصب سریع VPS قابل خواندن باشد؛ بدون وابستگی به ریپوی تکین. تغییرات در `main` ثبت می‌شوند؛ شاخه‌های آزمایشی تنها در صورت ضرورت کوتاه‌مدت و پس از ادغام قابل حذف‌اند.

## پوشه‌های مرجع

| مسیر | مسئولیت |
| --- | --- |
| `src/components/` و `src/pages/` | UI فارسی React، فرم‌ها، موبایل، پنل‌ها |
| `src/domain/` | منطق خالص انتخاب واحد، نیازسنجی، چارت و پیشنهاد |
| `src/demo/` | داده و API مصنوعی در حافظه/مرورگر؛ بدون احراز هویت یا ارسال پیام واقعی |
| `server/routes/` | API احراز هویت، دانشجو، مدیر، نیازسنجی، پیامک |
| `server/auth/`, `server/security/`, `server/sms/` | حفاظت حساب، Turnstile و فرستندهٔ مرکزی نیازپرداز |
| `server/db/` | داده و migration حافظه/JSON؛ آماده‌سازی برای دیتابیس رابطه‌ای در مقیاس دانشگاه |
| `extension/` و `mock-educational-system/` | افزونه و شبیه‌ساز آموزشیار؛ مستقل از هسته |
| `tests/` | تست‌های واحد/یکپارچگی/رگرسیون |
| `scripts/` | دستورهای **فعال** نصب، ساخت و smoke؛ `scripts/legacy/` آرشیو ابزار یک‌باره |
| `deploy/`، `compose.yaml` و `Dockerfile` | VPS، پراکسی، TLS، env خصوصی و پایداری داده |
| `docs/` | تصمیم‌ها، قوانین تأییدنشده، امنیت، گزارش و برنامهٔ توسعه |

## پاک‌سازی انجام‌شده

- ۲۲ اسکریپت پراکندهٔ `fix_*`، `test_*`، `update_*` و ابزارهای یک‌باره با **حفظ باینری/محتوا و تاریخچه** به `scripts/legacy/` منتقل شدند؛ هیچ ابزار فعالی که در `package.json` ثبت شده نبود. آرشیو «قابل اجرا در production» نیست.
- دستورهای رسمی فقط `bun run dev`، `bun run verify`، `bun run test`، `bun run lint`، `bun run build` و `bun run smoke:api` هستند. **آرشیو برای مستندسازی تاریخی است، نه اجرای تصادفی.**
- `src/components/AdminSmsCenter.tsx`، `src/components/GuestHumanCheck.tsx`، `server/sms/service.ts` و `server/security/turnstile.ts` در شاخه‌های مسئولیت جدا قرار گرفتند.
- یک تست استاتیک مستقل برای بازنگشتن `fix_*` و `test_*` به ریشه اضافه شد.

## بدهی‌های باقی‌مانده که نباید بی‌محابا حذف شوند

- **`data/darschyn-db.json` قبلاً در Git ردیابی شده است.** صرف وجود `.gitignore` آن را از تاریخچه حذف نمی‌کند. قبل از untrack باید هر نصب احتمالی را بررسی و نسخهٔ سالم را به مسیر پایدار خارج checkout منتقل کرد. حذف مستقیم فایل در Git ممکن است هنگام deploy نادرست دیتای زنده را پاک کند. هیچ دادهٔ واقعی دانشجو نباید به Git برگردد؛ ارزیابی مهاجرت/چرخش اسرار سابق لازم است.
- ZIP افزونه در ریشه از مسیر قدیمی آمده و تولید نسخهٔ جدید توسط `scripts/package-extension.cjs` انجام می‌شود. قبل از انتقال یا حذف آن، مرجع دانلود/بیلد را تست کن.
- چند پیش‌نویس PR قدیمی باقی‌اند. تغییرات مهم روی main جداگانه آورده شده‌اند؛ ادغام دسته‌جمعی بدون diff review و CI انجام نشود.
- انتقال پایگاه‌دادهٔ تک‌فرایندی به پایگاه‌دادهٔ تراکنشی، با قید یکتا روی نیازسنجی و مجوزها، مرحلهٔ قبل از توسعه برای همهٔ دانشگاه است.

## کنترل هر تغییر

1. مطمئن شو پوشهٔ مسئولیت صحیح انتخاب شده و secret/data/ZIP جدید ناخواسته commit نشده است.
2. `bun run repo:check` را اجرا کن (فقط ساختار، نه تست اجرایی)؛ سپس `bun run verify` و تست مرورگر.
3. نصب VPS همیشه از SHA مشخص و با پشتیبان/rollback جدا برای درس‌چین باشد.
4. از ریپوی تکین فقط الگوی مستند خوانده شده؛ نوشته، commit، secret یا تغییر در تکین ممنوع است.


## پاک‌سازی فوری سورس عمومی — ۱ نوامبر ۲۰۲۶

۲۲ اسکریپت اجراییِ منسوخ از `scripts/legacy/` حذف شدند؛ چند فایل رمزهای ثابت و دستور چاپ رمز محیط را در خود داشتند. مسیرهای فعال تست و ساخت در `scripts/` و `tests/` باقی‌اند. گیت `repo:public-check` از بازگرداندن فایل اجرایی به `scripts/legacy/` جلوگیری می‌کند. `scripts/legacy/README.md` تنها اطلاعیهٔ باقی‌مانده است.

این کار صرفاً حذف از HEAD است، **نه پاک‌شدن تاریخچهٔ Git، PR refs، Forkها یا نسخ قدیمی**؛ اعتبارنامه‌های مرتبط با فایل‌های منتشرشده باید باطل/تعویض شوند و تاریخچه جداگانه رسیدگی شود.
