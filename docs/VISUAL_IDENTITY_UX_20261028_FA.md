# بازطراحی زبان بصری درس‌چین — روز/شب، موبایل و مسیر واقعی دانشجو

تاریخ: ۱۴۰۵/۰۸/۰۶ — ۲۰۲۶/۱۰/۲۸  
دامنهٔ مجاز تغییر: **فقط مخزن `mohammadrezamie/DarsChin`**.

## تصمیم طراحی و اولویت‌های صاحب محصول

خواستهٔ تازه: «با اولویت UI و UX و فرانت‌اند و بک‌اند و قابل استفاده کردن پروژه و اصلاح رنگی کل پروژه و خوشگل‌تر کردنش از همه نظر». بنابراین پذیرش و کارکرد واقعی دانشجو و کیفیت واکنش‌گرایی مقدم بر جلوه‌های نمایشی است. تغییر رنگ نباید امنیت، قوانین دانشگاه، دسترس‌پذیری، صف کپی، پنل مدیر یا اپلیکیشن بک‌اند را خراب کند.

### سیستم بصری Aurora — نسخهٔ اول

- **هویت:** زمینهٔ خنثیِ روشن یا سرمه‌ای عمیق، ایندیگوی کنترل‌شده برای اقدام اصلی، بنفش برای جزئیات بصری، آبی فیروزه‌ای برای نشانه‌ها؛ وضعیت موفق/هشدار از رنگ برند مستقل است.
- **روز:** زمینه `#f5f7fc`، کارت `#ffffff`، متن `#192440`، متن دوم `#52617b`، عمل اصلی `#314bca`.
- **شب:** زمینه `#090f1e`، کارت `#101a2d`، متن `#f1f5ff`، متن دوم `#c0cbe0`، accent `#a5b4fc`.
- **خوانایی:** نسبت کنتراست متن اصلی روی کارت روز ۱۵٫۳۵ و شب ۱۵٫۹۴؛ متن دوم ۶٫۲۶ و ۱۰٫۶۵؛ دکمهٔ اصلی با متن سفید دست‌کم ۷٫۰۲. این اعداد مربوط به رنگ‌های اصلی‌اند، نه ممیزی جامع تک‌تک رنگ‌های utility.
- **فرانت مشترک:** کلاس‌های semantic برای هدر، هرو، کارت پیش‌نمایش، سطوح، CTA و داک؛ تغییرها محدود و قابل‌گسترش‌اند و Tailwind موجود حذف نشده است.
- **باگ ثابت CSS:** دستور `.darschin-page :where(h1,h2,h3,h4,p) {text-align:right}` باعث راست‌چین‌شدن متن‌هایی می‌شد که در خود کامپوننت `text-center` داشتند. حذف شده تا مرکزچین حقیقی لندینگ، هشدارها و empty stateها رعایت شود؛ جهت کلی سند همچنان RTL است.
- **فوکوس و حرکت:** outline واضح و امن، reduced-motion، forced-colors، و safe-area موبایل دست‌نخورده‌اند؛ تغییرات به فونت آنلاین وابسته نیستند.

### مسیر استفادهٔ دانشجو، نه دکور

- **لندینگ و ورود دمو:** CTA واضح و یکپارچه برای ورود سریع به دمو یا ساخت حساب؛ پیش‌نمایش با کارت و حالت شب هم‌خوان است.
- **پنل مدیریت و دانشجو:** توکن رنگ مشترک اما مسیرها و دسترسی‌های مجزا؛ داک موبایل و هدر اصلی با همین رنگ و سطح طراحی می‌شوند.
- **فرم‌های حساب:** ورود، ثبت‌نام و بازیابی زیر سیستم روز/شب قرار می‌گیرند؛ در فرم ورود، شمارهٔ همراه فارسی/عربی و `+98` بدون نیاز به تغییر صفحه‌کلید به‌درستی نرمال می‌شود. اعتبارسنجی و CAPTCHA سمت سرور حذف نشده.
- **وضعیت بک‌اند:** تمام APIها، محدودسازی سوءاستفاده، شرط بررسی OTP، منع از‌دست‌رفتن دیتابیس و دسترسی مدیر دست‌نخورده باقی می‌مانند؛ موفق‌شدن نسخهٔ فرانت به معنی رفع حادثهٔ قبلی VPS یا ارسال SMS واقعی نیست.

## گیت پذیرش

1. source SHA دقیق GitHub با فایل‌های آزمایشگاه تطبیق داده شود؛ ZIP تولیدی افزونه در صورت بازتولید جدا گزارش شود.
2. `bun run qa:full` با frozen lock، TypeScript، Vitest، Build و API smoke در دیتابیس ایزوله exit 0 بدهد.
3. Chromium/Playwright برای عرض‌های ۳۲۰/۳۶۰/۳۹۰/۴۳۰/۷۶۸/۱۰۲۴/۱۴۴۰، روی لندینگ، ورود، ثبت‌نام، دمو دانشجو و مدیر، و حالت روز و شب اجرا شود؛ overflow افقی و pageerror صفر؛ رنگ computed، کنتراست مهم و تراز مرکز را به‌جای صرف snapshot متنی بررسی کنیم.
4. کنترل‌های دسترسی و کارهای واقعی دانشجو مثل جابه‌جایی در داک و CTAها آزمایش شوند؛ **Safari/iPhone واقعی و سرعت اینترنت ایران** همچنان جداگانه لازم است.
5. قبل از مرج، فقط PR مربوط به همین دامنه ادغام شود؛ مخازن دیگر، VPS مشترک، داده‌ها و کلیدها مطلقاً بدون تغییر.

## برنامهٔ ادامه

پس از تثبیت رنگ/تایپوگرافی، اولویت بعدی مرور بصری صفحه‌به‌صفحهٔ دانشجو و مدیر (کارت درس، خروجی کپی، نیازسنجی، جدول‌های مدیر)، سپس بررسی شبکهٔ کند، loading/empty/error و رسیدن به API واقعی با محیط staging مستقل است. هیچ ادعای production-ready تا رفع خطای systemd، HTTPS، SMS/OTP واقعی، Backup/Restore و قوانین رسمی دانشگاه مجاز نیست.
