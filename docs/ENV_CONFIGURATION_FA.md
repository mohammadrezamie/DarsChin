# پیکربندی امن ENV درس‌چین — نسخهٔ متن‌باز (۱۴۰۵/۰۸/۱۰)

**هدف:** سورس اصلی همین ریپوی عمومی است؛ تنظیمات و داده‌های هر نصب خصوصی و مستقل‌اند. هیچ‌کس برای اجرای درس‌چین روی سرور خودش به رمز، شمارهٔ مالک، کلید پیامک یا دیتابیس سرور اصلی نیاز ندارد.

## فایل‌های نمونه و فایل‌های واقعی

- `.env.example` — الگوی اجرای محلی با Bun/Node.
- `deploy/.env.vps.example` — الگوی Docker Compose؛ از آن روی سرور خودتان فایل **خصوصی** `deploy/.env.vps` بسازید.
- `deploy/.env.staging.example` — الگوی systemd/Node برای محیط تست؛ نمونه را در مسیری خصوصی مانند `/etc/darschyn/staging.env` کپی کنید.

سه الگوی بالا **عمداً هیچ رمز، موبایل، دامنه، ایمیل، کلید سرویس یا SHA استقرار پرشده‌ای ندارند**. تمام فیلدهای حساس باید **فقط در فایل خصوصی همان سرور** تنظیم شوند. مقدار نمونهٔ `false` یا `log` برای سوئیچ‌ها، «کلید/هویت» نیست و به‌عنوان پیش‌فرضِ فاقد ارسال واقعی باقی مانده است.

**مهم برای VPS فعلی:** `git pull` فایل‌های نمونه را به‌روز می‌کند، نه فایل خصوصیِ از قبل موجود `deploy/.env.vps`. تا وقتی به سرور دسترسی و بکاپ معتبر ندارید، فایل خصوصی واقعی، حجم داده و کانتینر را تغییر ندهید. هرگز فایل نمونهٔ خالی را روی فایل واقعی کپی نکنید.

## توضیح متغیرها

| متغیر | کاربرد و روش تنظیم |
|---|---|
| `JWT_SECRET` | کلید خصوصی امضای نشست‌ها؛ حداقل ۳۲ بایت تصادفی. تغییر آن نشست‌های قبلی را باطل می‌کند. |
| `ROOT_OWNER_MOBILE` | شمارهٔ صاحب نصب، در قالب `09xxxxxxxxx`؛ متعلق به سرور همان نصب. |
| `ROOT_OWNER_PASSWORD` | رمز قوی و یکتای مدیر اصلی؛ در نصبِ دارای دیتابیس موجود، تغییر ENV به‌تنهایی هش ذخیره‌شده را عوض نمی‌کند. |
| `ROOT_OWNER_RECOVERY_KEY` | کلید بازیابی مستقل و قوی، متفاوت با رمز ورود؛ فقط روی سرور. |
| `DARSCHYN_ACCESS_MODE` | `owner_only` برای API مخصوص مالک یا `multiuser` برای حساب‌های دانشجویان. به‌تنهایی صفحات و دموهای استاتیک را مخفی نمی‌کند. |
| `DARSCHYN_REQUIRE_EXISTING_DB` | `false` فقط برای نصب اولیهٔ تأییدشده؛ بعد از بکاپ و آزمون بازگردانی `true` تا نبود دیتابیس موجب ساخت نسخهٔ خالی نشود. |
| `DARSCHYN_REGISTRATION_OTP_REQUIRED` | الزام تأیید مالکیت شمارهٔ دانشجو؛ برای ثبت‌نام واقعی با سرویس پیامکِ تأیید و تست‌شده `true` شود. |
| `SMS_PROVIDER` | `log` یعنی ارسال واقعی پیامک **انجام نمی‌شود**؛ برای سرویس واقعی نیازمند پیکربندی مجزاست. |
| `NIAZPARDAZ_API_KEY` | کلید خصوصی سرویس پیامک نیازپرداز؛ در Git قرار نگیرد. |
| `NIAZPARDAZ_SENDER_NUMBER` | خط/شمارهٔ فرستندهٔ تأییدشدهٔ همان نصب. |
| `NIAZPARDAZ_SMS_OTP_APPROVED` | `true` فقط بعد از تأیید متن OTP توسط ارائه‌دهنده و آزمون واقعی؛ پیش‌فرض امن `false`. |
| `TURNSTILE_ENABLED` | `true` با کلیدهای معتبر دامنهٔ نصب؛ `false` از کپچای تصویریِ اعتبارسنجی‌شدهٔ خود سامانه استفاده می‌کند. |
| `TURNSTILE_SITE_KEY` | کلید عمومی ویجت Turnstile، ولی در قالب نمونه خالی می‌ماند تا هر سرور کلید خودش را بگذارد. |
| `TURNSTILE_SECRET_KEY` | کلید خصوصی تأیید سمت سرور؛ هرگز داخل کلاینت یا Git قرار نگیرد. |
| `TURNSTILE_ALLOWED_HOSTNAMES` | دامنه‌های مجاز واقعی برای بررسی کپچا (با کاما جدا شوند). |
| `DARSCHYN_DOMAIN` | دامنهٔ واقعی سایت، فقط برای نصب با پراکسی Caddy اختصاصی. |
| `ACME_CONTACT_EMAIL` | ایمیل دریافت اعلان گواهی HTTPS برای Caddy اختصاصی. |
| `DARSCHYN_LOCAL_PORT` | پورت داخلی روی VPS مشترک با Nginx؛ قبل از تغییر باید upstream واقعی و اشغال‌نبودن پورت بررسی شود. |
| `DARSCHYN_RELEASE_SHA` | شناسهٔ Commit دقیقِ نسخهٔ تست‌شده (معمولاً ۴۰ نویسهٔ hex) برای مقایسهٔ سلامت استقرار. |
| `NODE_ENV`, `HOST`, `PORT` | تنظیمات اجرای Node و آدرس/پورت شنود در استقرار systemd/staging. |
| `DARSCHYN_DATA_DIR` | پوشهٔ دائمی دیتابیس **بیرون از Git و پوشهٔ Release**. برای Docker مسیر کانتینر `/app/data` و Volume جداگانه است. |

**نکتهٔ Compose:** در VPS مشترک با Nginx، تنظیمات خالیِ `DARSCHYN_DOMAIN` و `ACME_CONTACT_EMAIL` نباید اجرای فقط سرویس `darschin` را متوقف کنند؛ تنها نصب اختصاصی Caddy باید این دو را با مقادیر خصوصی واقعی پر کند.

## حداقل اقدامات امن برای هر نصب مستقل

1. سرور مستقل، فایل ENV خصوصی و بکاپ مستقل داشته باشید؛ هیچ کلیدی را از نویسنده یا از مخزن عمومی کپی نکنید.
2. فایل واقعی ENV را در Git ثبت نکنید. روی لینوکس دسترسی فایل را به حساب سرویس محدود کنید (مانند `chmod 600`).
3. برای سرور اشتراکیِ دارای Nginx، **Caddy همراه نمونهٔ اختصاصی را اجرا نکنید**. از Compose مخصوص localhost و پراکسی موجود استفاده کنید.
4. روی سرور اصلیِ فعلی، تا بازگشت دسترسی اپراتور **چیزی را ریست یا جایگزین نکنید**. مخصوصاً ENV نمونهٔ خالی، دیتابیس و volume.
5. کلیدهای مربوط به دیتابیس که سابقاً در تاریخچهٔ Git قرار داشتند، همچنان باید در محیط واقعی تعویض یا باطل شوند. حذف متن از HEAD یا نمونهٔ ENV، Git history و PRهای قدیمی را پاک نمی‌کند.

## کنترل خودکار در CI

`bun run repo:public-check` اکنون نام فایل‌های حساس، امضاهای شناخته‌شدهٔ توکن در متن، **مقادیر پرشدهٔ متغیرهای خصوصی در سه ENV نمونه** و آرشیوهای ZIP ردیابی‌شدهٔ افزونه را بررسی می‌کند. در گزارش، مقدار محرمانه چاپ نمی‌شود. بررسی حاضر جایگزین اسکن تمام تاریخچهٔ Git، فورک‌ها و PRهای قدیمی یا بازبینی سرور واقعی نیست.
