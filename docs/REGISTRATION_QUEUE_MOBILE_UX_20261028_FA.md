# UI/UX اول: بازطراحی کاربردی صف سریع انتخاب واحد

**تاریخ:** ۱۴۰۵/۰۸/۰۶ / ۲۰۲۶/۱۰/۲۸  
**مخزن قابل‌تغییر:** فقط `mohammadrezamie/DarsChin`

## اولویت قطعی مالک

مالک بارها تأکید کرده توسعه باید به شکل متوازن در **فرانت‌اند، بک‌اند، UI و UX** جلو برود، با **اولویت تجربه و ظاهر پرفکت و واقعی دانشجو روی موبایل، سپس دسکتاپ**؛ توسعهٔ پی‌درپیِ امنیت و زیرساخت، جایگزین این اولویت نیست. هدف، سامانهٔ خوش‌ساخت و قابل‌استفاده و آمادهٔ جذب دانشجوست. از این پس هر نوبت «ادامه بده» باید ابتدا نقص قابل‌مشاهدهٔ UI/UX یا مسیر واقعی استفاده را در صورت وجود شناسایی و اصلاح کند؛ تغییر بک‌اند با همان مسیر مرتبط و تست شود. این سند دستورهای فنی قبلیِ امنیت/حریم خصوصی را لغو نمی‌کند، فقط **ترتیب اجرای توسعه** را روشن می‌کند.

## مسئلهٔ مشاهده‌شده در «صف ثبت»

قبل از این تغییر، هر درس چهار دکمهٔ دائمیِ «بالا»، «پایین»، «کپی» و «ثبت شد» داشت. در عرض گوشی، دکمه‌ها به ردیف دوم می‌رفتند و ارتفاع لیست بی‌جهت زیاد می‌شد. تمایز عمل غالب (کپی سریع هنگام انتخاب واحد) و عمل مدیریتی (ویرایش ترتیب) ضعیف بود. کم‌کردن ارتفاع با بریدن نام کامل درس/استاد هم قابل‌قبول نیست.

## طرح انجام‌شده

- **حالت پیش‌فرض = ثبت سریع:** روی هر ردیف فقط دکمهٔ کپی کد و علامت انجام ثبت، با اندازهٔ لمس حداقل ۴۴ پیکسل، قرار دارند.
- **حالت چیدمان مستقل:** دکمهٔ «چیدمان» در سربرگ فقط وقتی بیش از یک درس وجود دارد فعال است؛ با ورود به آن، دکمه‌های حرکت بالا/پایین به‌جای کپی/تیک ظاهر می‌شوند. دکمهٔ «اتمام چیدمان» خروج روشن دارد، `aria-pressed` و `aria-controls` برای دسترس‌پذیری استفاده می‌شود. ذخیرهٔ ترتیب همچنان از callback موجود و سرور انجام می‌شود، بدون ثبت موفقیت جعلی.
- نام کامل درس **بدون line-clamp یا ellipsis** و استاد، روز/ساعت، گروه و کد در خط متای زیر همان ردیف قرار می‌گیرند. اگر نام بلند باشد به‌طور طبیعی می‌شکند، نه اینکه بی‌صدا مخفی شود.
- کدهای ساختگی DEMO، پیش‌نیاز نامعتبر، خواندن قوانین و سوابق دانشجو و محافظت از کپی غیرمجاز بدون تغییر و همچنان fail closed هستند. جزئیات شماره گروه و اخطارها قابل بازکردن‌اند، نه اینکه دکمهٔ پنجم دائمی به ردیف کوچک اضافه شود.
- هیچ API جدید، قانون دانشگاهی جدید یا تغییر مخزن دیگری برای این UI لازم نبود.

## آزمون اجراشده و شرط پذیرش

- بازسازی واقعی برنامه در Sandbox از فایل‌های GitHub؛ `bun run qa:full` روی نسخهٔ ترکیبی با کد جدید **exit 0**: `bun install --frozen-lockfile`، TypeScript، **۳۲۷ تست در ۶۰ فایل**، build افزونه/Vite/Express و API smoke مصنوعی موفق.
- آزمون **Chromium واقعی** روی بیلد production و `/demo/student` با حداقل دو درس در عرض‌های **۳۲۰، ۳۶۰، ۳۹۰، ۴۳۰، ۷۶۸، ۱۴۴۰ پیکسل**: کپی/تیک در هر ردیف، نداشتن کنترل اضافهٔ چیدمان در حالت عادی، ورود و خروج از چیدمان، ظاهرشدن کنترل‌های بالا/پایین، دسترسی بدون overflow افقیِ کل صفحه و صفر خطای JS همگی موفق شدند.
- تجربهٔ Safari/iOS واقعی، تست دانشجوی واقعی، مجوز و کد ارائهٔ واقعی و استقرار روی VPS هنوز جداگانه لازم‌اند. هیچ تست حقیقی آموزشیار انجام نشد.

**بخش بعدی:** استمرار پرداخت رابط دانشجو و پنل مدیریت، یکپارچه‌سازی ناوبری/فونت/تم در ۳۲۰ تا دسکتاپ، تست مشاهده‌پذیر قبل و بعد و اصلاح API مرتبط با همان مسیر تجربه. تغییرات امنیت و ذخیره‌سازی نگه داشته می‌شوند اما نباید همهٔ دورهای توسعه را به خود اختصاص دهند.
