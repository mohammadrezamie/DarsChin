# هماهنگ‌سازی تداخل‌سنج بصری دانشجو با موتور اعتبارسنجی سرور — ۱ نوامبر ۲۰۲۶

## مشکل واقعی
سرور برای ذخیرهٔ برنامه، زمان‌ها را با ارقام فارسی/عربی/لاتین، نیم‌فاصلهٔ نام روز و دقیقه‌های واقعی می‌سنجید؛ ولی پنل دانشجو و برنامه‌ریز هنوز با مقایسهٔ مستقیم رشتهٔ ساعت و تاریخ عمل می‌کردند. برای مثال «سه‌شنبه» و «سهشنبه» یا «۰۹:۰۰» و «09:00» ممکن بود دو پاسخ متفاوت بسازند. همچنین دو امتحان با تاریخ یکسان اما ساعت متفاوت به‌اشتباه «تداخل دقیق» شناخته می‌شدند.

## قرارداد واحد
- `src/domain/plan-conflicts.ts` مدل مشترک حداقلی برای ارائهٔ زمان‌بندی‌شده، استخراج تاریخ یکسان و تشخیص تداخل دقیقه‌ای را در اختیار API و هر دو UI می‌گذارد. کدهای جداگانهٔ تشخیص تداخل از کامپوننت‌ها حذف شده‌اند.
- `SchedulePlanner` از خروجی معتبر مشترک برای **تداخل قطعی کلاس** و **تداخل شروع دقیق امتحان** استفاده می‌کند. به‌صورت جداگانه، امتحان‌های هم‌روز با ساعت متفاوت/نامشخص را به‌عنوان هشدار **هم‌روزی، نیازمند بررسی** نگه می‌دارد؛ این‌ها ممنوعیت خودکار ایجاد نمی‌کنند.
- `StudentDashboard` از همان خروجی برای هشدار بالای صفحه استفاده می‌کند؛ تعارض کلاس و امتحان را با نام درس و روز/تاریخ صحیح توضیح می‌دهد. کلاس بی‌ساعت و ساعت‌های پشت‌سرهم بدون هم‌پوشانی، تداخل قطعی فرض نمی‌شوند.
- تست SSR در `tests/planner-ui-server-conflict-parity.test.tsx` با کلاس‌های فارسی/لاتین، امتحان هم‌روز با ساعت متفاوت، امتحان واقعاً هم‌ساعت و برنامهٔ زمان‌اعلام‌نشده بررسی می‌کند که برچسب‌های رابط با تصمیم سرور یکسان باشند.

**نکته:** هیچ قابلیت/منوی جدید و هیچ قانون علمی یا معارف دانشگاهی در این تغییر اضافه نشده است؛ تنها خطای تشخیص و نمایش اصلاح شده. اتصال فعلی VPS، دادهٔ واقعی و تکین دست‌نخورده‌اند. اجرای Typecheck/Vitest/Build دقیق PR و main شرط ادغام است.
