# برنامه تبدیل Vercel درس‌چین به محیط آزمایش کامل

**وضعیت بررسی: ۲۰۲۶/۱۰/۲۵ — راهنمای اجرایی، نه اعلام آماده‌بودن سایت.**

## نتیجه بررسی محیط متصل

- پروژه Vercel: `dars-chin`؛ خروجی فعلی Vite و HTML است.
- GitHub: شاخه `main` برای نسخه پایدار و `develop` برای Preview. اتصال خودکار Push آزمایش شده است.
- هنگام این بررسی، برای پروژه **هیچ Environment Variable** تعریف نشده بود و اتصال دیتابیس/Storage در فهرست Integrationهای تیم دیده نشد.
- در نتیجه مرورگر `/api/auth/*` و `/api/sync/*` را به Backend پایدار متصل نمی‌کند. دریافت HTML از مسیر API موفقیت سرویس نیست.
- فایل `data/darschyn-db.json` و حساب‌های نمونهٔ `server/db/seed.ts` را نباید به‌عنوان دیتابیس عمومی استفاده کرد.

## دو معماری ممکن

**گزینه A — Vercel برای UI + Express مجزا با Storage دائمی (کم‌ریسک‌ترین انتقال برای کد فعلی):**
1. راه‌اندازی Express در یک سرویس Node جداگانه با HTTPS و نام دامنه API مخصوص دمو.
2. اتصال مسیر `/api/*` سایت Vercel به آن سرویس از طریق Rewrite یا Proxy کنترل‌شده؛ حفظ Origin مرورگر و جلوگیری از CORS غیرضروری.
3. استفاده از مسیر دادهٔ جدا، خارج از مخزن، به همراه پشتیبان‌گیری و تست بازگردانی.
4. تست ورود/ثبت‌نام/بازیابی، نقش‌ها، دوره‌ها، برنامه‌ریز و همگام‌سازی روی دادهٔ **کاملاً ساختگی**.
5. پایش خطاها، محدودسازی نرخ درخواست، TLS و راه بازگشت به نسخه قبلی.

**گزینه B — API روی Vercel Functions + دیتابیس مدیریت‌شده:**
1. جداکردن Export برنامه Express از `listen` و سازگارکردن درخواست‌ها با Functions.
2. انتقال JSON محلی به Storage دارای سازگاری تراکنشی و کنترل هم‌زمانی.
3. بازنویسی بخش‌های I/O ذخیره‌سازی به صورت async و آزمون دقیق Auth/Sync.
4. مدیریت Secrets در Vercel و آزمون قطعی ذخیره و بازیابی بعد از Cold Start.
5. تست بار و محدودیت زمان اجرای Function؛ دمو و Production جدا.

**نکته:** فضای `/tmp` داخل Function موقتی است و دیتابیس کاربر محسوب نمی‌شود؛ یک فایل JSON در این مسیر تضمین ماندگاری یا سازگاری چند درخواست ندارد.

## قوانین ایمنی انتشار

- تا قبل از انتخاب و اتصال Storage دائمی، **نمی‌توان گفت سامانه کامل عملیاتی است**.
- ایجاد سرویس پولی، تغییر DNS، انتقال دیتابیس واقعی یا فعال‌کردن ورود عمومی نیازمند بررسی هزینه و تصمیم مشخص است.
- تنها Demo/Preview تحت کنترل توسعه تغییر می‌کند؛ `main` و دامنه Production بی‌مجوز تغییر نکنند.
- آزمون Green فرانت‌اند در Vercel جایگزین تست مستقل `bun run verify` و `bun run smoke:api` نیست.
- فهرست اشکالات مشاهده‌شده توسط آزمایش‌کننده با URL، Commit، مرورگر، خطوات بازتولید، انتظار/واقعیت و تصویر بدون داده حساس ثبت شود.

## مانع فعلی که باید رفع شود

برای عملیاتی‌شدن همه گردش‌ها یک Endpoint سرویس Backend با ذخیره‌سازی دائمی و ایزوله لازم است. اطلاعات فعلی Vercel هیچ سرویس دادهٔ متصل نشان نداد؛ بنابراین قدم بعدی توسعه باید **اتصال و تأیید عملی این زیرساخت** باشد، نه تولید صفحهٔ ظاهراً تکمیل‌شده.
