## ترتیب قطعی کار وقتی مالک می‌گوید «ادامه بده»

۱. ابتدا آخرین دستور مالک و مستندات مرتبط GitHub را بررسی کن؛ سپس **واقعاً رابط کاربری را توسعه بده یا دیباگ کن**. جمع‌کردن UI/UX حرفه‌ای، چشم‌نواز، قابل فهم، با هویت بصری یکپارچه و تجربهٔ سریع دانشجو اولویت این فاز است؛ بک‌اند را امن و کارا نگه‌دار و ایرادهای P0 عملکرد، امنیت و صحت داده را فوراً رفع کن. مستندات باید همراه کد باشند، نه جایگزین آن.

۲. مسیر کاربر: **لندینگ → دمو بدون حساب → پنل دانشجو → چارت/دروس ارائه‌شده → تداخل‌سنج و برنامهٔ هفتگی → صف سریع ثبت**؛ سپس پنل مدیریت و نیازسنجیِ اولویت‌دار، فرم‌ها، پیام‌های خطا و حالت‌های خالی. فوتر سازمانی از PR #38، و تغییرات آموزشی دقیق از PR #37 باید **بعد از رفع تعارض و تست** با UI همگرا شوند.

۳. **طراحی:** زبان فارسی روان و راست‌به‌چپ صحیح (راست‌چین اجباری برای همهٔ محتوا ممنوع)، Vazirmatn محلی، تعادل فضای خالی و تراکم اطلاعات، تیتر و رنگ و سایهٔ هماهنگ، حالت تیره/روشن خوانا، انیمیشن محدود و احترام به `prefers-reduced-motion`. کاربر باید در نخستین اسکرین دمو و مسیر بعدی را به‌روشنی بفهمد؛ کدهای دمو و اطلاعات آموزشی غیرمصوب نباید «قطعی» نشان داده شوند.

## رفع تداخل شاخه و ادامهٔ دیباگ — ۲۰۲۶/۱۰/۲۶

- وضعیت آغاز این نوبت: PR #34 با `main` واگرا بود (پیش از همگام‌سازی ۴۱ کامیت عقب و ۵۷ کامیت جلو)، `mergeable=false`. رفع تعارض **روی همان شاخه** انجام شد تا شاخهٔ دیگری انباشته نشود.
- یک merge commit دووالدی روی شاخه ساخته شد؛ درخت نهایی از `main=1f28e634` آغاز و **فقط ۱۷ فایل مربوط به UI/UX، تست و مستندات همان PR** از نسخهٔ بازبینی‌شدهٔ شاخه روی آن اعمال شدند. GitHub پس از عملیات `mergeable=true`، `behind=0` نشان داد. بررسی SHA پرونده‌های خارج از محدوده (از جمله `AGENTS.md`، دفتر تصمیمات، اسناد حادثهٔ VPS، مسیرهای API و sync، پیکربندی TypeScript/Vitest و تست ایزولهٔ DB) نشان داد آن‌ها از آخرین `main` بدون تغییر حفظ شده‌اند.
- تست `tests/rtl-visual-design.test.tsx` با اصلاح معتبر `main` همگرا شد: تشخیص هر دو شکل `=== 'Tab'` و `!== 'Tab'` به‌علاوهٔ `Shift+Tab` و `preventDefault`. یک الگوی escape نادرست در تلاش نخست تصحیح و منبع دوباره خوانده شد.
- مسیر کپی شمارهٔ گروه که در UI قدیمی وجود داشت، بدون بازگرداندن دکمهٔ پنجم به ردیف تنگ موبایل، به جزئیات بازشوندهٔ هر ردیف انتقال یافت؛ لمس ۴۴ پیکسل، برچسب ARIA و محافظ `rulesReady` را دارد. کپی کد درس همچنان در خود ردیف و اطلاعات درس/استاد/زمان به‌صورت کامل دیده می‌شوند.
- **تفاوت مهم:** `mergeable=true` فقط رفع تعارض Git است؛ تأیید رفتار، موبایل، امنیت و آماده‌بودن برای مشتری نیست. در این نشست **Bun/Vitest/TypeScript/build، تست واقعی Browser/Safari، API smoke و Vercel Deploy اجرا نشده‌اند**. وضعیت Check مربوط به Vercel همچنان **build-rate-limit** است. PR باید تا احراز گیت کامل روی SHA نهایی Draft بماند و به `main` merge نشود.

## بازتنظیم پس از هفتهٔ نخست — دستور ۲۰۲۶/۱۰/۲۷

مالک صریحاً گفت با گذشت تقریباً یک هفته از هدف یک‌ماهه، سرعت اثرگذاری روی **فرانت‌اند، بک‌اند، UI و UX** باید افزایش یابد. پس از ادغام داک چهارمقصدی دانشجو و سربرگ فشرده و نوار sticky مدیریت (PR #52 و #53)، تمرکز تغییرات جدید بر واقعی‌بودن فرم‌های CRUD و نیازسنجی و مسیر انتخاب دروس است، نه افزودن آپشن تزئینی.

- **هفتهٔ دوم:** فرم و جدول مدیریت قابل کار در موبایل و دسکتاپ، وضعیت بارگذاری/خطای معتبر، نیازسنجی مدیر گروه، سفر انتخاب درس → تداخل‌سنج → صف سریع کپی. بهبود بصری فونت، تراکم، کنتراست و دسترس‌پذیری باید همراه با مرورگر واقعی باشد.
- **هفتهٔ سوم:** پایلوت کوچک با بک‌اند قابل مشاهده، پیامک واقعی و حساب تأییدشده، تست permission و گزارش نیازسنجی، backup/restore و استقرار مستقل staging از تکین؛ پیش‌نیازهای مدارک دانشگاهی نباید حدس زده شوند.
- **هفتهٔ چهارم:** تست iPhone/Safari، فشار و رگرسیون، رفع باگ‌های پیدا شده، onboarding، عملکرد و انتشار SHA-معلوم با rollback. اگر گیت عملیاتی VPS/امنیت باز باشد انتشار عمومی ممنوع است.

**اقدام اجرایی این نوبت:** فرم‌های CRUD مدیر با retry، خطای روشن، محافظ race و تأیید حذف درون‌صفحه بازطراحی شدند؛ در [گزارش CRUD](ADMIN_CRUD_RELIABILITY_20261027_FA.md) شواهد QA و مرزهای واقعی توضیح داده شده است. تکین و سایر مخازن دست‌نخورده‌اند.
