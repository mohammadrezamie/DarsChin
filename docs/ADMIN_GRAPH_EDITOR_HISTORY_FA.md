# کارگاه گرافی پیش‌نیاز و هم‌نیاز — تاریخچهٔ امن، چینش RTL و تحلیل اثر

> **وضعیت ۳۱ اکتبر ۲۰۲۶ — OWN-103:** پیاده‌سازی و تست محدود در PR #71، بدون مرج به main. این سند قرارداد پذیرش و حدود واقعی قابلیت است.

## هدف و صورت مسئله

مدیر باید بتواند درس‌های یک چارت را مانند نقشهٔ ذهنی به یکدیگر متصل کند؛ پیوند پیش‌نیاز فلش پیوسته و هم‌نیاز خط‌چین است. صرفاً نگاه‌کردن به درسِ ترم بعدی کافی نیست: تصمیم دربارهٔ اثر یک اتصال بر **تمام مسیر تا فارغ‌التحصیلی** باید با گراف همان چارت و وابستگی‌های مستقیم/غیرمستقیم بررسی شود. دادهٔ خام ID فقط در API استفاده می‌شود، نه در تجربهٔ اصلی مدیر.

## رفتار قابل استفاده — انجام‌شده در این مرحله

1. **تاریخچهٔ پیش‌نویس (Undo/Redo):** انتخاب مبدأ، مقصد، نوع رابطه و پاک‌کردن انتخاب در تاریخچهٔ محلی و محدود به ۴۰ گام ثبت می‌شوند. Undo یک مرحله را برمی‌گرداند و Redo همان مرحله را دوباره اجرا می‌کند. تغییر جدید پس از Undo شاخهٔ Redo را پاک می‌کند. تغییر چارت یا ثبت موفق، تاریخچهٔ محلی را پاک می‌کند. کلیک دکمه‌های بازگشت/انجام دوباره روی **دادهٔ ثبت‌شدهٔ سرور هیچ اثری ندارد**.
2. **پیش‌نمایش قبل از ذخیره:** روی یک اتصال سادهٔ معتبر، موتور از همان `analyzeCurriculumDependencies` استفاده می‌کند و اثر احتمالی اتصال بر تعداد درس‌های پایین‌دستی یکتا و عمق بلندترین مسیر را برای **همهٔ نیاکان مرتبط در همان چارت** حساب می‌کند. تکرار الماسی دو بار شمرده نمی‌شود؛ هم‌نیاز زنجیرهٔ پیش‌نیازی را طولانی نمی‌کند؛ برای OR هشدار «مسیر ممکن» وجود دارد؛ چرخه یا مرجع نامعتبر پیش‌نمایش معتبر نمی‌گیرد.
3. **پیش‌نمایش حذف:** فقط وقتی پیوند به **یک قانون سادهٔ مستقل و بی‌ابهام** اشاره کند، اثر حذف روی زنجیره نمایش داده می‌شود و تأیید حذف همچنان جداگانه است. قانون‌های AND/OR، رابطه‌های مشترک یا زمینه‌مند بدون بررسی پیشرفته از روی گراف حذف نمی‌شوند.
4. **دو شیوهٔ چینش:** نمای «زنجیره» (پیش‌فرض) گره‌ها را با عمق واقعی DAG از راست به چپ می‌چیند؛ نمای «ترم چارت» بر اساس ترم پیشنهادی می‌چیند. جهت رسم از مبدأ سمت راست به مقصد سمت چپ است. در گراف خراب/چرخه‌دار، نمای زنجیره‌ای به جای ساختن عمق جعلی به نمای ترمی برمی‌گردد و پیام خطا حفظ می‌شود.
5. **حفاظت در زمان ذخیره:** هنگام POST/DELETE، تغییر چارت، تغییر نوع رابطه، انتخاب گره یا drag/drop تازه غیرفعال‌اند تا پاسخ دیرهنگام یک ذخیره روی چارت تازه اعمال نشود. دسترسی نهایی توسط API و `prerequisite.manage` بررسی می‌شود؛ این رابط، مجوز مستقل نیست.

## تعهدات باز، مهم و اجباری

- **Undo/Redo قوانین *ثبت‌شده*:** هنوز انجام نشده. قبل از پیاده‌سازی باید نسخه/ETag هر چارت، کنترل هم‌زمانی دو مدیر، audit trail و بازیابی با تأیید جداگانهٔ سرور طراحی شوند. تاریخچهٔ پیش‌نویس نباید «بازگردانی تغییر سرور» نامیده شود.
- **ویرایش گرافیکی قوانین مرکب AND/OR، شرط مردودی و قوانین حوزه‌مند:** در رابط پیشرفته موجودند، اما تبدیل مستقیم و ایمنشان از روی لبهٔ سادهٔ گراف هنوز تکمیل نشده.
- **نمای سه‌بعدی واقعی** باید اختیاری و سبک باشد؛ در موبایل و برای دسترس‌پذیری، نمای دوبعدی جایگزین اصلی باقی بماند.
- **اهمیت تا فارغ‌التحصیلی** فعلاً شاخص ساختاری DAG است، نه مدل پیش‌بینی واقعی چندترمی با قیود ارائهٔ درس/ظرفیت/انتخابی و سوابق دانشجو. این هدف همچنان P0 است.
- **چارت معارف دانشگاه آزاد کارشناسی پیوستهٔ غیرپزشکی:** تا دریافت تمام جزئیات، استثناها و چیدمان از مالک و تأیید او، قانون رسمی فرض یا اعمال نشود.
- **حاکمیت:** هیچ قابلیت/دکمه/نقش خارج از درخواست مالک اضافه نشود؛ این کنترل‌های جدید زیر همان کارگاه گرافیِ صریحاً درخواستی‌اند. تنها درس‌چین اصلاح شده است؛ تکین و VPS و تولید بدون تغییر؛ PR Draft باقی می‌ماند.
