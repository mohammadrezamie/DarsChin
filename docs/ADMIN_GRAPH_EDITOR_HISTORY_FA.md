# کارگاه گرافی پیش‌نیاز و هم‌نیاز — تاریخچهٔ امن، چینش RTL و تحلیل اثر

> **وضعیت ۳۱ اکتبر ۲۰۲۶ — OWN-103:** پیاده‌سازی و تست محدود در PR #71، بدون مرج به main. این سند قرارداد پذیرش و حدود واقعی قابلیت است.

## هدف و صورت مسئله

مدیر باید بتواند درس‌های یک چارت را مانند نقشهٔ ذهنی به یکدیگر متصل کند؛ پیوند پیش‌نیاز فلش پیوسته و هم‌نیاز خط‌چین است. صرفاً نگاه‌کردن به درسِ ترم بعدی کافی نیست: تصمیم دربارهٔ اثر یک اتصال بر **تمام مسیر تا فارغ‌التحصیلی** باید با گراف همان چارت و وابستگی‌های مستقیم/غیرمستقیم بررسی شود. دادهٔ خام ID فقط در API استفاده می‌شود، نه در تجربهٔ اصلی مدیر.

## رفتار قابل استفاده — انجام‌شده در این مرحله

1. **تاریخچهٔ پیش‌نویس (Undo/Redo):** انتخاب مبدأ، مقصد، نوع رابطه و پاک‌کردن انتخاب در تاریخچهٔ محلی و محدود به ۴۰ گام ثبت می‌شوند. Undo یک مرحله را برمی‌گرداند و Redo همان مرحله را دوباره اجرا می‌کند. تغییر جدید پس از Undo شاخهٔ Redo را پاک می‌کند. تغییر چارت یا ثبت موفق، تاریخچهٔ محلی را پاک می‌کند. کلیک دکمه‌های بازگشت/انجام دوباره روی **دادهٔ ثبت‌شدهٔ سرور هیچ اثری ندارد**.
2. **پیش‌نمایش قبل از ذخیره:** روی یک اتصال سادهٔ معتبر، موتور از همان `analyzeCurriculumDependencies` استفاده می‌کند و اثر احتمالی اتصال بر تعداد درس‌های پایین‌دستی یکتا و عمق بلندترین مسیر را برای **همهٔ نیاکان مرتبط در همان چارت** حساب می‌کند. تکرار الماسی دو بار شمرده نمی‌شود؛ هم‌نیاز زنجیرهٔ پیش‌نیازی را طولانی نمی‌کند؛ برای OR هشدار «مسیر ممکن» وجود دارد؛ چرخه یا مرجع نامعتبر پیش‌نمایش معتبر نمی‌گیرد.
3. **پیش‌نمایش حذف:** فقط وقتی پیوند به **یک قانون سادهٔ مستقل و بی‌ابهام** اشاره کند، اثر حذف روی زنجیره نمایش داده می‌شود و تأیید حذف همچنان جداگانه است. قانون‌های AND/OR، رابطه‌های مشترک یا زمینه‌مند بدون بررسی پیشرفته از روی گراف حذف نمی‌شوند.
4. **دو شیوهٔ چینش:** نمای «زنجیره» (پیش‌فرض) گره‌ها را با عمق واقعی DAG از راست به چپ می‌چیند؛ نمای «ترم چارت» بر اساس ترم پیشنهادی می‌چیند. جهت رسم از مبدأ سمت راست به مقصد سمت چپ است. در گراف خراب/چرخه‌دار، نمای زنجیره‌ای به جای ساختن عمق جعلی به نمای ترمی برمی‌گردد و پیام خطا حفظ می‌شود.
5. **حفاظت در زمان ذخیره:** هنگام POST/DELETE، تغییر چارت، تغییر نوع رابطه، انتخاب گره یا drag/drop تازه غیرفعال‌اند تا پاسخ دیرهنگام یک ذخیره روی چارت تازه اعمال نشود. دسترسی نهایی توسط API و `prerequisite.manage` بررسی می‌شود؛ این رابط، مجوز مستقل نیست.

## تعهدات باز، مهم و اجباری

- **Undo/Redo قوانین *ثبت‌شده*:** گام محدود و ایمن در OWN-104 پیاده‌سازی شده: *فقط آخرین تغییر ثبت‌شدهٔ همان چارت* با نسخهٔ معتبر و مجوز قابل بازگردانی است؛ Undo/Redo دلخواه از هر نقطهٔ تاریخچه و بازپخش دسته‌ای همچنان ممنوع/ناتمام است. تاریخچهٔ پیش‌نویس با تاریخچهٔ سرور یکی نیست.
- **ویرایش گرافیکی قوانین مرکب AND/OR، شرط مردودی و قوانین حوزه‌مند:** در رابط پیشرفته موجودند، اما تبدیل مستقیم و ایمنشان از روی لبهٔ سادهٔ گراف هنوز تکمیل نشده.
- **نمای سه‌بعدی واقعی** باید اختیاری و سبک باشد؛ در موبایل و برای دسترس‌پذیری، نمای دوبعدی جایگزین اصلی باقی بماند.
- **اهمیت تا فارغ‌التحصیلی** فعلاً شاخص ساختاری DAG است، نه مدل پیش‌بینی واقعی چندترمی با قیود ارائهٔ درس/ظرفیت/انتخابی و سوابق دانشجو. این هدف همچنان P0 است.
- **چارت معارف دانشگاه آزاد کارشناسی پیوستهٔ غیرپزشکی:** تا دریافت تمام جزئیات، استثناها و چیدمان از مالک و تأیید او، قانون رسمی فرض یا اعمال نشود.
- **حاکمیت:** هیچ قابلیت/دکمه/نقش خارج از درخواست مالک اضافه نشود؛ این کنترل‌های جدید زیر همان کارگاه گرافیِ صریحاً درخواستی‌اند. تنها درس‌چین اصلاح شده است؛ تکین و VPS و تولید بدون تغییر؛ PR Draft باقی می‌ماند.


## OWN-104 — بازگردانی واقعی آخرین تغییر ثبت‌شده با کنترل نسخه (۳۱ اکتبر ۲۰۲۶)

**انجام‌شده در PR #71 (فقط شاخهٔ Draft):**

- سرویس `server/services/academic-rule-history.ts` برای محاسبهٔ SHA-256 محتوای قوانین یک چارت، دفتر ثبت رویدادهای `ACADEMIC_RULE_ADDED`، `ACADEMIC_RULE_DELETED` و `ACADEMIC_RULE_REVERTED` با شناسهٔ مدیر، عکس دقیق قانون و نسخهٔ قبل/بعد، و کنترل آخرین عملیات.
- افزودن و حذف قوانین در API اصلی با `If-Match` اختیاری برای سازگاری با کلاینت‌های قدیمی کنترل می‌شوند؛ **کارگاه گراف همیشه نسخهٔ فعلی را همراه درخواست می‌فرستد**. درخواست نسخهٔ قدیمی یا نامعتبر با `409 Conflict` رد می‌شود. دسترسی API همچنان `prerequisite.manage` را نیاز دارد و نیازمند نقش مدیر است؛ روت استثنای مجاز است.
- مسیر خصوصی `GET /api/curriculum/rules/history/:curriculumId` وضعیت نسخه و ۲۰ رویداد اخیر قابل مشاهده برای مدیر را برمی‌گرداند. روت می‌تواند وقایع مدیران را بررسی کند؛ مدیر تفویض‌شده فقط سوابق خودش را می‌بیند. عملیات متقابل مدیران بدون مجوز برنمی‌گردد.
- مسیر `POST /api/curriculum/rules/history/:curriculumId/revert` فقط وقتی **آخرین تغییر گراف همان چارت** با نسخه و شناسهٔ رویداد درخواستی منطبق باشد، و مجوز مدیر معتبر باشد، عمل معکوس را ثبت می‌کند. Undo یک ADD را حذف و Undo یک DELETE را با همان شناسه بازمی‌گرداند؛ هر Undo خودش رویداد جدید است و یک Redo امن به‌شکل بازگردانی آخرین Undo امکان‌پذیر می‌شود. در بازیابی یک DELETE، حضور درس‌ها، حوزهٔ رشته/ورودی/گرایش، تکراری‌نبودن رابطه و نداشتن چرخه دوباره سمت سرور کنترل می‌شوند.
- رابط گراف بخش جمع‌شوندهٔ «تاریخچهٔ تغییرات ثبت‌شدهٔ چارت»، تأیید دومرحله‌ای، دکمهٔ بازیابی از اختلاف نسخه، غیرفعال‌سازی تغییرات تا دریافت نسخهٔ معتبر، و جداسازی بازگردانی سروری از Undo/Redo پیش‌نویس دارد. Demo فقط نسخهٔ آزمایشی را نشان می‌دهد و ادعای تاریخچهٔ واقعی نمی‌کند.

**آزمون‌های واقعی این مرحله:** `tests/academic-rule-history.test.ts`، `tests/academic-rule-history-api.test.ts` با Supertest و احراز هویت واقعی، به‌همراه آزمون‌های گراف قبلی؛ ۲۹ مورد مرتبط تا این لحظه موفق، دو سناریوی افزودهٔ سطح HTTP هم موفق. `bun run lint` و `bun run build` موفق و `bun run smoke:api` در Sandbox روی داده‌های موقت با exit 0 پاس شده‌اند. **توجه:** محیط Sandbox ترکیبی از snapshot قدیم و فایل‌های همگام‌شدهٔ هدفمند از GitHub است؛ از موفقیت آن نباید نتیجه گرفت کل HEAD واحداً verify شده یا مرورگر واقعی لمس/drag-drop را گذرانده است.

**باز برای مراحل بعد:** تاریخچهٔ قابل جست‌وجو و بازگردانی دلخواهِ نسخه‌های قدیمی فقط پس از طراحی snapshot/transaction سازگار با تغییرات هم‌زمان؛ آزمون E2E مرورگر واقعی، صحت بصری روی موبایل و نقشه‌های بزرگ، رندر سه‌بعدی اختیاری، و مدل رسمی چندترمی تا فارغ‌التحصیلی. هیچ تغییر خودسرانه‌ای در قانون معارف، نقش‌ها، TNA یا Production انجام نشده است.


## OWN-105 — امن‌سازی ویرایشگر پیشرفتهٔ AND/OR در کنار نقشه (۳۱ اکتبر ۲۰۲۶)

مدیر در حالت پیشرفته حالا ابتدا چارت را انتخاب می‌کند و تنها **دروس فعال همان چارت** برای مقصد و تمام شرط‌های ترکیبی نمایش داده می‌شوند؛ با تغییر چارت، مقصد و درخت شرط بازنشانی می‌شود. هم‌زمان نسخهٔ محتوایی `If-Match` دریافت می‌شود؛ ذخیره و حذف با همان نسخه از تعارض هم‌زمان دو مدیر محافظت می‌شوند. خطای ثبت پیشرفته ورودی مدیر را پاک نمی‌کند؛ تا تازه‌سازی صریح نسخه و بازبینی دوباره، فرم مجوز ارسال ندارد. در API طرح شرط با Zod سخت‌گیرانه کنترل می‌شود: هر برگ درس معتبر/غیرخالی و هر گروه «و/یا» با حداقل دو شرط پرشده. ویرایش مستقیم لبه‌های گروهی از روی خود گراف هنوز کارِ آینده است؛ دکمهٔ حذف گراف همچنان فقط برای قانون مستقل و بی‌ابهام فعال است.

**تست‌های مرتبط:** `tests/admin-academic-rule-scope.test.ts` چهار آزمون ساختار Zod و scoping/If-Match/Recovery دارد؛ به‌علاوهٔ تست‌های قبلی Undo/Redo و نقشه در اسناد OWN-103 و OWN-104.
