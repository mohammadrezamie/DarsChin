# استاندارد تجربه کاربری درس‌چین — برنامه بازطراحی مرحله‌ای

> وضعیت: **دموی آزمایشی**. این سند به معنای تأیید قوانین آموزشی دانشگاه آزاد، اتصال پایدار Backend یا آماده‌بودن سرویس برای استفاده واقعی نیست.

## اولویت‌های محصول

1. **اول موبایل:** ناوبری قابل استفاده با یک دست، عرض‌های ۳۲۰، ۳۷۵ و ۴۳۰ پیکسل، اهداف لمسی مناسب، فرم‌های خوانا در Safari و بدون اسکرول افقی ناخواسته.
2. **فارسیِ خوانا:** فونت Vazirmatn از فایل‌های موجود مخزن، متن‌های راست‌به‌چپ، اعداد قابل مقایسه و پیام‌های خطای مفهوم؛ بدون وابستگی به فونت نصب‌شده روی دستگاه.
3. **تم سه‌حالته:** روز، خودکار بر اساس دستگاه، شب؛ سازگاری با ذخیره‌سازی غیرفعال، refresh اولیه و نوار مرورگر موبایل.
4. **پنل مدیریت:** گروه‌بندی بخش‌ها، جست‌وجوی ناوبری، لینک مستقیم به هر بخش از طریق `?tab=`، کنترل دسترسی مدیر ارشد، و بازگشت/جلو رفتن مرورگر.
5. **فرم‌های مدیریتی قابل اعتماد:** بارگذاری/خطا/فهرست خالی سه حالت جداگانه‌اند؛ شکست درخواست نباید به معنی «هیچ داده‌ای ثبت نشده» نمایش داده شود. عملیات تغییر داده باید فقط پس از پاسخ موفق API تأیید شوند.
6. **داده آزمایشی بدون فریب:** هنگام استفاده از `/demo/admin` و `/demo/student` داده‌ها ساختگی‌اند و هیچ ادعایی درباره اجرای API یا قواعد رسمی نداریم.

## قرارداد فعلی ناوبری مدیریت

- مسیرهای `/admin?tab=courses` و `/demo/admin?tab=courses` بانک دروس را باز می‌کنند.
- شناسه‌های معتبر در `src/utils/admin-navigation.ts` تعریف می‌شوند. مقدار نامعتبر به پیشخوان برمی‌گردد.
- بخش‌های `users`، `diagnostics`، `academic-settings` و `logs` فقط برای مدیر ارشد انتخاب‌پذیرند. اعتبارسنجی اصلی دسترسی **همچنان در سرور** اجباری است؛ کنترل فرانت صرفاً یک لایه تجربه کاربری است.
- جست‌وجوی بخش‌ها تنها فهرست ناوبری را فیلتر می‌کند و اطلاعات کاربران یا درس‌ها را به بیرون نمی‌فرستد.
- انتخاب یک بخش در موبایل منو را می‌بندد؛ Escape و دکمه بستن تمرکز را برمی‌گردانند، و در وضعیت باز اسکرول پس‌زمینه محدود است.

## چک‌لیست پذیرش بصری و عملکردی

- [ ] Safari در ۳۲۰، ۳۷۵ و ۴۳۰ پیکسل: نوار بالایی، انتخاب‌گر تم، باز/بستن منو، اسکرول فهرست مدیریت، فرم CRUD، حذف نمونه و دکمه‌های ذخیره بدون بیرون‌زدگی.
- [ ] Android Chrome: ورود به یک فیلد با فونت ۱۶ پیکسل بدون زوم ناخواسته و حفظ صفحه هنگام باز شدن کیبورد.
- [ ] مرورگر دسکتاپ: سایدبار، جست‌وجو، رندر جدول و تغییر `?tab` با Back/Forward.
- [ ] مدیر عادی: لینک مستقیم به بخش‌های مخصوص مدیر ارشد به پیشخوان برگردد. سرور درخواست فاقد مجوز را رد کند.
- [ ] خاموشی API: پیام خطا و «تلاش دوباره» جایگزین وضعیت خالی کاذب شود.
- [ ] روشن/تاریک/خودکار: تضاد رنگ، وضوح فونت و وضعیت نوار مرورگر در refresh بررسی شوند.
- [ ] هیچ اطلاعات واقعی دانشجویی در گزارش‌ها، اسکرین‌شات‌ها و داده‌های دمو ثبت نشود.

## آزمون و انتشار

- تست‌های منبع در `tests/admin-navigation.test.tsx` و `tests/admin-responsive-design.test.tsx` تغییرات ناوبری/تم را پوشش می‌دهند. **وجود تست به معنی اجرای موفق آن نیست**؛ قبل از release باید `bun run lint`، `bun run test` و `bun run build` اجرا و ثبت شوند.
- انتشار Vercel تا بازشدن سهمیه روزانه متوقف است: [Issue #23](https://github.com/mohammadrezamie/DarsChin/issues/23).
- اتصال API و دیتابیس پایدار، احراز هویت واقعی و ماندگاری داده‌ها مسیر جداگانه‌ای دارند: [Issue #16](https://github.com/mohammadrezamie/DarsChin/issues/16).
- تغییر قوانین دانشگاه آزاد فقط پس از دریافت و تأیید اطلاعات صاحب پروژه مجاز است: [پرونده جمع‌آوری قوانین](ACADEMIC_RULES_INTAKE_FA.md).

## مراحل بعدی

- مرحلهٔ بعد: آزمون مرورگر واقعی و رفع موارد مشاهده‌شده، بازبینی سلسله‌مراتب صفحهٔ دانشجو و وضعیت‌های خطای انتخاب واحد.
