# وضعیت پروژهٔ درس‌چین — گزارش تاریخی و روش بررسی وضعیت روز

> **مهم:** بخش‌های زیر آرشیو گزارش‌های مهر ۱۴۰۵ (اکتبر ۲۰۲۶) هستند. عبارت‌هایی مانند «تست نشده»، «PR باز است» یا «بیلد موفق» وضعیت **همان تاریخ** را توصیف می‌کنند و الزاماً وضعیت امروز مخزن نیستند. برای وضعیت امروز باید `main`، آخرین PRها، آزمون‌های GitHub Actions و مستندات جدید بررسی شوند.

## ۲۴ اکتبر ۲۰۲۶ ــ یکپارچه‌سازی تاریخی و تست دود API

در آن تاریخ تغییرات PR بزرگ اولیه بر مبنای `main` پاک‌سازی‌شده و مجهز به Bun در شاخهٔ `feat/landing-sync-rebased-20261024` منتقل شدند. اصلاح مستقل حذف دادهٔ محرمانه، Runner قابل اجرای `bun run verify` و `bun.lock` واحد حفظ شدند. به دلیل محدودیت سهمیهٔ Actions، گردش‌کار قدیمی آزمون خودکار در آن انتقال وارد نشده بود.

**شواهد ثبت‌شده در همان دوره:** آزمون `bun run verify` در محیط ایزولهٔ Node 24 و Bun 1.4.4 با خروج صفر، نصب قفل‌شده، TypeScript، Vitest، بستهٔ افزونه، Vite و سرور انجام شد. تست دودِ Express با دیتابیس موقت و رمزهای مصنوعی، `GET /api/health` با پاسخ `ok` و مسیر نامعتبر `/api/*` با JSON ۴۰۴ را مشاهده کرد. ایرادهای تایپ OTP و تفکیک نتیجهٔ اعتبارسنجی رفع و آزمون بازیابی رمز به ساعت مشخص وابسته شد.

**محدودیت همان گزارش:** DOM و محتوای واقعی آموزشیار بررسی نشده بود؛ Vercel تنها فرانت‌اند را نشان می‌داد. راه‌اندازی کاربر واقعی، SMS، HTTPS، بوت‌استرپ Root، بکاپ/Restore و ذخیره‌سازی روی VPS به تأیید مستقل نیاز داشتند. هیچ استقرار تولیدی بر اساس خود این گزارش انجام نشد.

## ارزیابی اولیهٔ قدیمی (۱۳ اکتبر ۲۰۲۶)

مبنای اولیه `main` با SHA `61837f949d015e899c46a5be55e9070eafaf4667` و شاخهٔ توسعه `fix/ci-regression-tests` با SHA `055db1a9231e8f415f5e7ab9f03406110fd0a02f` بود. این شناسه‌ها **تاریخی** هستند و نباید مبنای گزارش امروز یا استقرار بدون تست دوباره قرار گیرند.

| حوزه | مشاهده در ارزیابی تاریخی | نیاز آزمون در آن زمان |
| --- | --- | --- |
| رابط React/Vite | ساخت پیش‌نمایش موفق؛ کاهش قطعهٔ اولیهٔ JS از ۶۹۹٫۴۱ به ۲۷۱٫۰۶ کیلوبایت | موفقیت ظاهری، صحت API را ثابت نمی‌کند |

### خطرهای ثبت‌شده در همان ارزیابی

- `login()` نتیجهٔ شیء برمی‌گرداند و در نسخهٔ قدیمی مثل Boolean استفاده می‌شد؛ بنابراین مسیریابی اشتباه رخ می‌داد.
- خروجی افزونه با `schemaVersion: 2.0` و دادهٔ `course`، `courseClass` و `_meta` با برخی نوع‌های قدیمی `1.0` یکسان نبود.
- پارسر ساعت افزونه احتمال خطا داشت؛ درگاه سرور تنها مقادیر قابل تفسیر را پذیرفت و از حدس‌زدن ساعت خودداری شد.
- تعداد ثبت‌نام‌شدهٔ واقعی از افزونه قابل استناد نبود؛ مقدار غیرمعتبر نباید به آموزشیار نسبت داده شود.
- تاریخچهٔ همگام‌سازی و ایزوله‌سازی تست نیاز به آزمون دوام داشت.
- الگوی قدیمی ENV و `JWT_SECRET` نیاز به بازبینی داشتند.
- در بیلد Vercel آن زمان ۱۱ هشدار npm audit (۳ متوسط، ۷ بالا، ۱ بحرانی) گزارش شده بود؛ بدون گزارش تازه و تعیین وابستگی مربوطه، ارتقای اجباری و کورکورانه ممنوع بود.
- اسکریپت‌های یک‌بارمصرف و ZIPهای قدیمی نیازمند ردیابی مبنای ساخت بودند؛ حذف بدون شناخت مرجع ممنوع بود.

## تغییرات تاریخی شاخهٔ توسعه

- `server/sync/reconciliation.ts` برای دادهٔ چندلایهٔ افزونه، هویت منبع پایدار، حذف تکرار و رد ساعت/ظرفیت نامعتبر طراحی شد.

## بهبودهای ظاهری در گزارش قدیمی

صفحهٔ اصلی واکنش‌گرا، پیش‌نمایش تعاملیِ درس‌های ساختگی، توضیح درست مرحلهٔ دریافت/تطبیق، حذف آمار غیرواقعی، پایش Sync مدیر با مجوز، پیوندهای فارسی و ورود مستقل دانشجو/مدیر، و تقسیم صفحه‌ها به قطعات Lazy-load ایجاد شدند. نمونهٔ پیش‌نمایش `https://dars-chin-git-fix-ci-regression-tests-tna12.vercel.app/` در آن تاریخ HTTP ۲۰۰ فرانت‌اند را می‌داد، نه API واقعی. الگوهای systemd/Nginx نیز صرفاً نمونه بودند و به معنی تغییر سرور نبودند.

## یادداشت تاریخی احراز هویت و OTP ــ ۱۳ اکتبر

- شمارهٔ همراه ایرانی در `server/auth/normalize-mobile.ts` با ارقام فارسی/عربی و پیش‌شماره‌ها به شکل `09xxxxxxxxx` تبدیل می‌شد؛ مسیر permissive قبلی که همهٔ رشته‌ها را می‌پذیرفت حذف شد.
- اعتبارسنجی Zod بازیابی رمز، دادهٔ نامعتبر را پیش از فراخوانی متدهای رشته‌ای رد کرد و آزمون‌های مربوطه اضافه شدند.
- `scripts/verify.sh` در گزارش قدیمی برای نصب Bun، بررسی TypeScript، تست‌ها و ساخت به ترتیب معرفی شد. ادعای اجرایی‌بودن آن در همان لحظه بدون اجرای واقعی کافی نبود.
- مسیرهای ارسال/تأیید OTP ورودی نامعتبر، قالب شماره، هدف `login`/ `password_recovery`، مهلت انقضا و جلوگیری از استفادهٔ مجدد را بررسی کردند.
- کد بررسی رقم OTP و شماره در یکی از نسخه‌های قدیمی Escape اشتباه داشت که اصلاح شد.
- چالش بازیابی رمز پس از «تأیید» باید تا زمان مصرف در endpoint بازیابی حفظ و پس از تکمیل حذف می‌شد؛ پاک‌سازی زودهنگام ایراد داشت و رگرسیون آن ثبت شد.
- `ZodError.issues` در نسخهٔ جدید Zod جای ویژگی قدیمی `errors` را گرفت و مسیرهای HTTP ۴۰۰ آزمایش شدند.
- چالش CAPTCHA/OTP منقضی و مصرف‌شده باید از صف موقت حذف شود، اما چالش بازیابیِ تأییدشده تا مصرف نهایی بماند.
- تست OTP با شماره‌های ساختگی ۱۱رقمی و CAPTCHA واقعیِ آزمایشی پایدارتر شد؛ کد OTP نباید در پاسخ API ارسال شود.

**وضعیت اجرای همان گزارش:** بخش‌های متوالی توسعه در محیط‌های مختلف آزمون کامل نشده بودند؛ بسیاری از تغییرها صرفاً در سورس و برخی Buildها دیده می‌شدند. این جمله گواه شکست امروز نیست.

## دسترسی دانشجو و مالک در گزارش تاریخی

- ارسال Sync با `campusId` دلخواهِ غیرمرتبط با پروفایل دانشجو ممنوع شد.
- نقش Root نباید صرف تطبیق شمارهٔ همراه در Login یا `/api/auth/me` به فرد داده شود؛ هویت بوت‌استرپ معتبر `usr-super` هم باید بررسی شود.
- ثبت‌نام عمومی فقط نقش دانشجو می‌دهد؛ بازیابی Root موجود در دیتابیس قدیمی نیاز به فرایند آفلاینِ تأییدشده داشت.
- تست‌ها با `DARSCHYN_DATA_DIR` موقت و حساب Root مصنوعی از دیتابیس واقعی جدا شدند.
- جلوگیری از تکرار شماره، مصرف دوبارهٔ OTP و خرابی تصادفی دادهٔ تست در همان دوره ثبت شده بود.

## روش بررسی وضعیت امروز

1. SHA `main`، PRهای باز و نتیجهٔ آخرین `Typecheck / Tests / Build` را روی GitHub بخوانید.
2. وضعیت درخواست‌های جاری را از [دفتر تصمیمات مالک](OWNER_DECISIONS_FA.md) و [فهرست مستندات](INDEX.md) استخراج کنید.
3. برای ویژگی، یکی از برچسب‌های زیر را استفاده کنید:
   - **بازبینی سورس:** فقط کد خوانده شده، اجرا نشده است.
   - **آزمون واحد موفق:** تست خودکار روی SHA نام‌برده سبز است.
   - **ساخت موفق:** Build تولیدی روی SHA نام‌برده انجام شده است.
   - **آزمون دادهٔ نمونه:** فقط Fixture یا محیط مصنوعی بررسی شده است.
   - **آزمون زنده:** رفتار منبع بیرونی یا محیط نصب واقعی در زمان مشخص بررسی شده است.
4. فایل `PROJECT_STATUS.md` را بدون شواهد به‌عنوان وضعیت لحظه‌ای تغییر ندهید و از آن برای توجیه اتصال به VPS فعلی استفاده نکنید.
