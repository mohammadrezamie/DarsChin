# فهرست متمرکز کاربران، جست‌وجو و خروجی Excel مدیر ارشد

**۲۰۲۶/۱۰/۲۸ — گام اجرایی خواستهٔ مالک**  
مخزن: فقط `mohammadrezamie/DarsChin`. هیچ عملیات نوشتنی روی تکین، سایر مخازن، DNS، VPS یا شماره‌های واقعی انجام نشده.

## نیاز عملیاتی

- روت اصلی باید کاربرها را با نام، موبایل و شمارهٔ دانشجویی جست‌وجو کند؛ دادهٔ دانشجو و مدیر را جدا و بدون درخواست شناسهٔ داخلی مدیریت کند.
- مدیر تفویض‌شده فقط مدیرهایی را می‌بیند که API مجاز به نمایش آن‌هاست؛ پنل دانشجو هرگز نام مدیرها، مجوزها یا مسیر خروجی را نمایش نمی‌دهد.
- روت با فیلتر نقش می‌تواند فایل **XLSX واقعی** شامل نام، موبایل، شماره دانشجویی، نقش، وضعیت تأیید موبایل و نام مجوزها را برای گزارش اداری دریافت کند. فایل پسورد، recoveryKey، OTP یا توکن ندارد.
- خروجی در سرویس با `requireSuperAdmin` محافظت و درخواست با نقش نامعتبر رد می‌شود. `Cache-Control: private, no-store` و رویداد ممیزی `USER_DIRECTORY_EXPORTED` با فقط نقش/تعداد/قالب ثبت می‌شود، **نه محتوای کاربران**. سقف محافظتی ۲۰ هزار ردیف است.
- فایل Office Open XML با `adm-zip` موجود در پروژه ساخته می‌شود؛ سلول‌ها از نوع `inlineStr` هستند و محتوای XML پاک‌سازی می‌شود، نه فرمول Excel. متن فارسی، چیدمان راست‌به‌چپ و قالب `.xlsx` است.
- در نمای روت، جست‌وجوی فوری با نام/موبایل/شماره دانشجویی و فیلتر student/admin/super-admin اضافه شده؛ برای کاربران غیرروت امکان تغییر نقش حذف شده تا رابط به عملیات غیرمجاز دعوت نکند.

## گیت واقعی و محدودیت‌ها

- آزمون ایزوله `tests/admin-user-excel.test.ts` چهار سناریو را واقعاً اجرا کرد: ساخت ZIP/OOXML بدون formula، رد خروجی بیش از سقف، رد دسترسی مهمان/مدیر عادی و رد فیلتر غیرمجاز، خروجی نقش دانشجو و ثبت audit؛ **۴/۴ پاس**.
- TypeScript روی Sandbox بازیابی‌شده با فایل‌های منطبق با SHA برای بخش‌های مرتبط **exit 0** و build React/Express/افزونه **exit 0** شد.
- این **معادل گیت کامل آخرین SHA main نیست**: Sandbox از snapshot قدیمی‌تر بازسازی شد و تمامی فایل‌های ۳۰۰+ نسخهٔ جدید همگام نشده‌اند؛ بنابراین PR باید تا `bun run qa:full` کامل روی SHA نهایی و تست مرورگر/UI، **Draft و unmerged** بماند.
- فایل OOXML از نظر ساختار در تست Vitest بررسی شده، ولی آزمون بازکردن فایل روی Excel واقعی/Numbers یا Safari/iPhone هنوز انجام نشده است.
- رابط جست‌وجو روی مجموعهٔ دریافتی کار می‌کند و pagination سمت سرور/ایندکس دیتابیس برای ده‌ها هزار کاربر هنوز پیاده نشده؛ ۲۰ هزار ردیف محدودیت موقت و نیازمند طراحی مقیاس است.

## خط قرمز حریم خصوصی

خروجی Excel امکان «ارسال پیامک دسته‌جمعی» نیست. پیش از ارسال اخبار، بازاریابی یا اطلاع‌رسانی به دانشجویان باید هدف پردازش شماره‌ها، مجوزهای داخلی، رضایت/حق انصراف در صورت لزوم، قالب پیام، rate limit و ثبت نتیجهٔ ارسال مشخص و تأیید شود. هیچ انتقال خودکار شماره‌ها به سرویس بیرونی در این تغییر وجود ندارد.

**مراحل باقی‌مانده:** اجرای کامل QA روی کد فعلی، تست مرورگر موبایل/دسکتاپ، بازبینی permissionهای ایجاد/ارتقای مدیر، pagination امن و تجربهٔ صفر‌تا‌صد مدیریت بدون شناسهٔ خام. چارت معارف نیز طبق تصمیم OWN-055 منتظر گفت‌وگو و منبع معتبر مالک می‌ماند.

## تکمیل جریان روت واحد و تجربهٔ جدول — ۲۰۲۶/۱۰/۲۹

- API تغییر نقش `/api/admin/users/:id/role` دیگر **هیچ درخواست ایجاد `super-admin` دوم** را نمی‌پذیرد و حساب رزروشدهٔ `usr-super` را با **شناسهٔ ثابت** محافظت می‌کند، نه با شمارهٔ موبایل هاردکدشده.
- API دوم `/api/admin-management` نیز از ایجاد/ارتقای روت دوم و تغییر هویت روت اصلی جلوگیری می‌کند. ایجاد مدیر معمولی از UUID یکتا استفاده می‌کند تا برخورد شناسه در درخواست‌های هم‌زمان کم شود. APIهای حساس همچنان سروری محافظت می‌شوند.
- پنل مدیریت روت دارای **جست‌وجوی نام، موبایل، شمارهٔ دانشجویی؛ فیلتر نقش؛ صفحه‌بندی ۲۵/۵۰/۱۰۰ ردیفی** و کنترل Download Excel است. فیلتر و صفحه‌بندی محلی برای پایلوت است؛ paging سمت سرور برای داده‌های انبوه هنوز باید پیاده شود.
- **تست واقعی:** روی ۳۲۸ فایل غیرباینری با hash دقیق GitHub، `bun run qa:full` برابر **۳۵۸/۳۵۸ تست در ۶۵ فایل، TypeScript، build، API smoke exit 0**. سناریوهای تازهٔ تلاش ساخت روت دوم، تغییر روت و ارتقای مدیریتی غیرمجاز پوشش داده شده‌اند. در Chromium با دادهٔ کاملاً synthetic و پاسخ API mock، جدول روت در **۳۲۰/۳۶۰/۳۹۰/۴۳۰/۷۶۸/۱۴۴۰**، جست‌وجوی شماره دانشجویی، کنترل‌های صفحه‌بندی، نبود گزینهٔ ارتقای روت دوم، نبود overflow و خطای مرورگر قبول شد.
- **مرز شفاف:** تست UI از Mock API و JWT ساختگی برای نمایش UI استفاده کرد و جایگزین آزمون ورود واقعی/مجوز واقعی نیست. مجوز واقعی Excel با Supertest و فایل OOXML ایزوله تأیید شد. بازکردن Excel روی Office/Numbers، Safari فیزیکی، بار واقعی، VPS و انتشار همچنان بررسی مستقل می‌خواهد.
